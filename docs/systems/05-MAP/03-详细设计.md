## 3. 审批门实现（FR-PUB-04）🔴

```go
// biz/map/approval_gate.go
type Gate struct {
    dispatchRepo DispatchRepo
    approvalRepo ApprovalRepo
}

// Publish 是**唯一**发布入口。三条校验任一失败即拒绝。
func (g *Gate) Publish(ctx context.Context, unitID string, operator Actor) error {
    u, err := g.dispatchRepo.Get(ctx, unitID)
    if err != nil { return err }

    // 校验 1：状态
    if u.ApprovalState != StateApproved {
        return ErrNotApproved            // "MAP_NOT_APPROVED"
    }
    // 校验 2：禁自批
    if u.Approver == "" || u.Approver == u.SubmittedBy {
        return ErrSelfApproval           // "MAP_SELF_APPROVAL"
    }
    if operator.Type == ActorAutomation {
        return ErrAutomationCannotPublish // "MAP_AUTOMATION_DENIED"
    }
    // 校验 3：可见性
    if u.VisibilityDefault != "private" && u.VisibilityOverrideReason == "" {
        return ErrVisibilityNoReason     // "MAP_VISIBILITY_NO_REASON"
    }
    // 校验 4：熔断
    if err := g.breaker.Check(ctx, u.Targets); err != nil {
        return err                       // "MAP_ACCOUNT_PAUSED"
    }
    // 校验 5：总量上限
    if err := g.quota.Check(ctx); err != nil {
        return err                       // "MAP_QUOTA_EXCEEDED"
    }

    // 记录审计（**先于**实际发布，便于事后追溯）
    g.approvalRepo.Record(ctx, &ApprovalRecord{
        DispatchUnitID: unitID, Action: "publish", Actor: operator.ID,
        ActorType: operator.Type, FromState: StateApproved, ToState: "published",
        VisibilityAtAction: u.VisibilityDefault,
    })
    return nil   // 放行，由 publish_usecase 执行
}
```

### 3.1 三条铁律的代码级保障

| 铁律 | 代码保障 | 兜底 |
|------|---------|------|
| **无 approve 不得 publish** | `Gate.Publish` 校验 1 | **数据库约束**：`publish_state='published'` 要求 `approval_state='approved'` |
| **禁自批** | `Gate.Publish` 校验 2 + `Approve` 时校验 | 同上 |
| **默认私密** | `intake` 时恒设 `private`；校验 3 | `platforms.yaml` 的 `visibility_default` 配置 |

> 🔴 **双保险**：应用层校验 + 数据库约束。只有应用层校验时，绕过应用层的直接 DB 操作会破坏不变量。

### 3.2 Approve 操作的禁自批

```go
func (g *Gate) Approve(ctx context.Context, unitID string, approver Actor) error {
    u := g.dispatchRepo.Get(ctx, unitID)
    if approver.ID == u.SubmittedBy      { return ErrSelfApproval }
    if approver.Type == ActorAutomation  { return ErrAutomationCannotApprove }
    if u.ApprovalState != StateDraft     { return ErrInvalidState }
    // 流转 + 审计
}
```

## 4. 发布执行流程

```
Gate.Publish 放行
  → publish_usecase.Execute(ctx, unitID, operator)
     → 幂等检查（同 unit 已 published 则直接返回已有回执）
     → 取 VariantSet 媒体文件（对象存储签名 URL / 本地路径）
     → 规格转码（FR-PUB-02）：按平台 Capability 转码
         失败 → 记录，**不阻断**（草稿保留，UI 提示）
     → 文案改写（FR-PUB-03）：按平台长度限制改写
         超长 → 截断 + 提示
     → 解密凭据（内存中使用，用完清零）
     → 对每个 target 串行发布（**避免并发打爆同一平台**）：
         adapter.Publish()
           ├─ 成功 → 写 PublishReceipt（post_id/url/visibility/operator）
           │         更新账号健康（consecutive_failures = 0）
           └─ 失败 → consecutive_failures++
                      错误脱敏后记 last_error
                      触发熔断检查
                      asynq 重试（指数退避，最多 3 次）
                      3 次仍失败 → 死信 + 告警 + 草稿保留
     → 更新 DispatchUnit.publish_state
     → 发 mm.map.feedback.v1（若平台支持 analytics，延迟拉取）
```

## 5. 凭据安全（FR-PUB-05 / NFR-MAP-03）🔴

```go
// data/map/credential_vault.go
type CredentialVault interface {
    Store(ctx context.Context, acctID string, cred Credential) (ref string, err error)
    Load(ctx context.Context, ref string) (*Credential, error)   // 解密，仅内存使用
    Delete(ctx context.Context, ref string) error
}
```

**实现要点**

| 措施 | 说明 |
|------|------|
| 加密 | 用 `pkg/crypto` 对称加密；密钥取自环境变量/密钥管理，**不入库** |
| 存储 | 数据库中只存 `credential_ref`（引用）+ 密文 |
| 使用 | `Load` 解密后**仅在函数作用域**使用，返回前 `defer` 清零 |
| 日志 | 全局脱敏中间件：token / cookie / authorization / password 一律 `***` |
| 传输 | 凭据**不进** `DispatchUnit` 契约（契约已明确不传凭据） |

> 🔴 **代码审计项**：全局搜索日志输出路径，确认无凭据明文；`PublishRequest` 中不得出现凭据字段。

## 6. 熔断（NFR-MAP-04）

```go
// biz/map/circuit_breaker.go
type Breaker struct{ repo AccountRepo; cfg BreakerConfig }

func (b *Breaker) OnFailure(ctx context.Context, acctID string) {
    a := b.repo.Get(ctx, acctID)
    a.ConsecutiveFailures++
    switch {
    case a.ConsecutiveFailures >= b.cfg.AccountFailThreshold:   // 默认 3
        a.Health = paused
        a.PausedUntil = time.Now().Add(b.cfg.PauseDuration)      // 默认 30min
        metrics.Alert("account_paused", acctID)
    case a.ConsecutiveFailures >= 2:
        a.Health = degraded
    }
    b.repo.Save(ctx, a)
    b.checkPlatform(ctx, a.ChannelID)   // 平台级检查
}

func (b *Breaker) checkPlatform(ctx context.Context, channelID string) {
    rate := b.repo.PlatformFailRate24h(ctx, channelID)
    if rate > b.cfg.PlatformFailRateThreshold {   // 默认 0.5
        b.repo.PauseAllAccounts(ctx, channelID)
        metrics.Alert("platform_paused", channelID)   // 需人工介入
    }
}
```

**凭据失效特殊处理**：鉴权失败时 `health = credential_invalid`，**不清凭据**（便于排查），UI 引导重新授权。

## 7. 排期与速率（FR-PUB-06）

### 7.1 双模式

```go
func (s *Scheduler) Schedule(ctx context.Context, u *DispatchUnit) error {
    for _, target := range u.Targets {
        p, _ := publisher.Get(target.PlatformKey)
        if p.Capability().NativeSchedule && !u.ForceLocalWorker {
            u.ScheduleMode = native
            // 调平台 API 设排期，post_id 在排期时即返回
        } else {
            u.ScheduleMode = local_worker
            // asynq 定时任务，到点调 Gate.Publish
            asynq.EnqueueAt(u.ScheduledFor, publishTask(u.ID))
        }
    }
}
```

### 7.2 速率治理

| 层 | 维度 | 默认 |
|----|------|------|
| 账号级 | 两次发布最小间隔 | 5 分钟 |
| 平台级 | 单平台每小时上限 | 20 |
| 全局 | 24h 发布总量 | 100（超限硬阻断） |

**拟人化节奏**：排期时间加 ±随机偏移（±3 分钟），避免整点批量发布的可识别模式。

### 7.3 落地语义（2026-10-19，实现即 `worker/map`）

§7.1 的 `asynq.EnqueueAt(...)` 伪码在落地时依据以下裁决具体化，语义等价但更抗停摆：

1. **触发方式：30s 到期扫描**（`map.publish.due-scan` 周期任务）替代建单时 EnqueueAt——服务停机重启后错过的时间点会被下一轮扫描自然补发（概要设计 §7 已声明「错过时间点会延迟」可接受），且 Cancel/改态天然吊销（扫描谓词与执行复核双层状态过滤，无需任务撤回协调）。
2. **拟人化偏移为确定性**：`FNV-1a(unit_id)` 映射进 [-jitter, +jitter]，同一单元偏移恒定——既防整点批量模式，又避免「每轮扫描重掷骰子」造成的点火时序抖晃。
3. **执行复核**：`map.publish.due` 处理器先做状态复核（approval!=approved / published / publishing / 非 local_worker → no-op），再走 PublishUsecase 全链（五校验 + 幂等锁 + 回执跳过已成平台）。
4. **重试/死信**：`MaxRetry = conf.retry.max_attempts`（默认 3），指数退避用 asynq 默认 RetryDelayFunc（`base_delay: 30s` 与默认值量级吻合，精确曲线属 asynq 实现细节）；**终态错误不占重试额度**（审批态/建单态/配额/确认类/已发表锁竞争 = 收尾不掷回），耗尽后写 `result=deadletter` 审计 + 日志告警 + 草稿保留（失败态不回退，人工重发立即发走 REST 同链）。
5. **🔴 代发身份（ADR-MAP-11）**：operator = 审批人（human）。门写死拒绝 automation（不可关闭）与本节「到点调 Gate.Publish」存在矛盾，2026-10-19 拍板：审批即含「内容+可见性+目标+时间窗」完整授权，worker 只做时间触发器；真相可查 = publish 伴随审计 `reason="via=scheduler"` + IP/UA 空；`confirm_public=true` 视为审批人对可见性的既确认（非 private 建单已有 override_reason 前置 + 审批时人工过目）。
6. **运维总闸**：`map.yaml schedule.local_worker_enabled`（默认 false）= 扫描注册与扫描体双层把关，重启生效；REST 立即发不受闸影响。

### 7.4 表现回流落地语义（2026-10-19，实现即 `worker/map/analytics_worker.go`）

§4 的「发 mm.map.feedback.v1」在落地时按以下裁决具体化：

1. **asynq 周期轮询替代事件扇出**：MM_PUB stream 未建（04-开发进度 §6.1 依赖表），V1 以
   `map.analytics.scan` 周期任务（节奏 = `feedback.fetch_interval`，默认 6h）扫 30 天内带
   post_id 的回执，逐条经适配器 `FetchAnalytics` 拉取后**直接写快照表**。快照表本身即回流
   真值；跨系统事件发射（TT/IC 消费侧）待 stream 建成后补发——事件只是传播媒介，不补不丢数据。
2. **🔴 feedback.enabled=false 为运维总闸**（双层把关：Start 不注册周期任务 + pull 内部短路）。
   总闸关闭时 REST/CSV 兜底（回执导出）不受影响。
3. **时序快照 append-only**：表现数随时变化，同一回执**在扫描窗内**每轮追加一行（无去重
   约束）——历史轮次保留供趋势观察，`LatestByReceipt` 读最新一条即「当前表现」。
   **窗沿冻结语义（诚实口径）**：回执出 30 天窗后快照停止追加，最新一行即窗口沿冻结值；
   `GetAnalytics` 在 `published_at` 出窗时置 note 明示「快照停止更新」，陈旧度由消费方按
   `fetched_at` 判断——不伪装新鲜。窗常量 `bizpub.FeedbackScanWindow` 由 worker 与读侧
   共用，两侧口径同源。
4. **凭据纪律**：worker 全程不触碰凭据。`FetchAnalytics(acct, postID)` 签名不含凭据；
   真实适配器接入时由适配器内部经 vault 解密即清。拉取鉴权失败 →
   `health=credential_invalid`（凭据保留，同 circuit_breaker 纪律），下轮自然过滤。
   适配器原始错误进日志前**必须经 `SanitizeUpstreamError` 截断**（与发布路径同纪律——
   防真实适配器在 error 文本中夹带 url query token；publishadapters 单测同时断言
   `FetchAnalytics` 错误不含凭据引用）。
5. **槽位解析与诚实补偿**：渠道枚举走 `ChannelRepo.ListChannelsByPlatform` 直查（无分页
   钳制——REST 分页 `ListChannels` 的 pageSize≤200 护栏不得叠加到内部取全量路径）。
   平台唯一渠道 → 直接锚定；**多槽位平台 → 经回执发布账号反查其渠道锚定发布槽位**
   （真实发布回执恒带 `account_id`），能力判定恢复「渠道快照优先」口径（运营在槽位快照
   关闭 analytics 时不被旁路）；锚定槽位已删/已停用/平台不一致、或回执无账号可锚 =
   **诚实 skipped**（不臆测槽位）。
6. **终态/可重试分流**：渠道停用/账号不可用/未声明 analytics/适配器未注册 = 终态 skip；
   上游抖动/平台错误 = 本轮 failed，下一轮周期自然补拉（无独立重试队列——6h 间隔足够大）。
7. **闭环回指**：单元可查时回填 `variant_id`（发布→表现→反哺选题的闭环字段，可空）。

## 9. 错误处理与错误码

| 错误码 | 场景 | 处置 |
|--------|------|------|
| `MAP_NOT_APPROVED` 🔴 | 未审批即发布 | 拒绝 |
| `MAP_SELF_APPROVAL` 🔴 | 自批 | 拒绝 + 审计记录 |
| `MAP_AUTOMATION_DENIED` 🔴 | 自动化身份审批/发布 | 拒绝 + **critical 告警** |
| `MAP_VISIBILITY_NO_REASON` 🔴 | 非 private 且无理由 | 拒绝 |
| `MAP_ACCOUNT_PAUSED` | 账号熔断中 | 拒绝，提示恢复时间 |
| `MAP_QUOTA_EXCEEDED` | 总量超限 | 拒绝，需人工解除 |
| `MAP_ADAPTER_NOT_FOUND` | 平台适配器不存在 | **明确报错**，不静默降级 |
| `MAP_CAPABILITY_UNSUPPORTED` | 平台不支持该能力 | 明确报错 + 建议替代平台 |
| `MAP_CREDENTIAL_INVALID` | 凭据失效 | 停用账号 + 引导重新授权（**不清凭据**） |
| `MAP_TRANSCODE_FAIL` | 规格转码失败 | **不阻断**，草稿保留 + 提示 |
| `MAP_UPSTREAM_ERROR` | 平台返回错误 | 脱敏后转译为可读提示 + 重试 |
| `MAP_RATE_LIMITED` | 平台限流 | 退避重试（尊重 `Retry-After`） |

**错误脱敏**：平台原始错误经 `translator` 映射为可读文案，**不暴露原始堆栈或凭据片段**。
