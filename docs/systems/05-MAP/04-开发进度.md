## 7. 风险与砍单顺序

### 7.1 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| **企业资质申请周期长** | **高** | 高（国内平台不可用） | **立即启动申请**（周期常 2–8 周）；Phase 2 先做国外平台 |
| Phase 2 容量不足 | **高** | 高 | 见 §6.2 方案 A/B |
| 适配器被平台改版破坏 | **高** | 中 | 适配器隔离；失败明确报错；草稿保留 + ZIP 兜底 |
| 账号被封 | 中 | 高 | 熔断 + 隔离 + 限流 + 规模克制（Q7） |
| 凭据泄露 | 低 | **极高** | 加密 + 脱敏 + 内存清零 + 安全测试 |
| 平台限流 | 中 | 中 | 尊重 `Retry-After` + 退避 + 速率治理 |
| 视频号等无 API 平台 | **确定** | 低 | 诚实标注「不支持」，不模拟操作 |

### 7.2 砍单顺序（延期时**自上而下**砍）

```
1. 平台数量：4 → 3 → 2（保 YouTube + B站）
2. FR-PUB-06 排期（降为仅本机 worker 到点发）
3. FR-PUB-03 文案改写（降为仅长度截断，不做语气改写）
4. FR-PUB-02 规格转码（降为仅分辨率，不做码率/时长自适应）
5. 熔断平台级（降为仅账号级）
────────── 以下为 🔴 不可砍 ──────────
   FR-PUB-04 审批门（含禁自批）
   FR-PUB-05 账号池与凭据加密
   FR-PUB-07 发布回执与审计
   默认私密（NFR-MAP-01）
   日志脱敏（NFR-MAP-03）
```

> 🔴 **MAP 的不可砍项全是安全与合规**。这不是保守——**公开发布不可逆**，一旦发出就无法撤回。与其事后补救，不如前置防线。

## 8. 验收门禁

| 门禁 | 检查 |
|------|------|
| **审批门禁** 🔴 | 无 approve 直接 publish → **失败**；自批 → **失败**；自动化身份 → **失败** |
| **私密门禁** 🔴 | 随机 20 次发布，可见性**全部** private/unlisted，无一 public |
| **凭据门禁** 🔴 | 代码审计：加密存储 + 日志无明文 + 内存清零 |
| **回执门禁** | 随机 20 条回执，全部含 post_id / 时间 / 可见性 / 操作者 |
| **幂等门禁** | 同一 unit 并发发布 5 次，只产生 1 条回执 |
| **熔断门禁** | 注入连续失败，账号自动暂停且**不影响**其他账号 |
| **适配器门禁** | 未注册的 platform_key → **明确报错**，不静默降级 |
| **契约门禁** | `DispatchUnit` 100% 通过 JSON Schema |
