## 2. 核心算法

### 2.1 热度归一化（`biz/tt/normalize.go`）

#### L1 平台内

```
rank_pct = clamp( (rank_total - rank) / max(rank_total - 1, 1), 0, 1 )
#   rank=1（榜首）→ rank_pct≈1.0；rank=rank_total（榜尾）→ 0.0
#   无榜数据（rank<0）→ rank_pct 不参与，权重按比例重分配给其余因子

eng_rate   = (likes + comments) / max(views, 1)         # 有曝光时
eng_pct    = percentile_rank( log1p(likes+comments),
                              within=(platform, category),
                              window=rolling 7d )        # 无曝光时退化为对数分位
```

> **分位计算**：滚动 7 日窗口内的经验分位，用 Redis 有序集合维护（score=log1p(互动数)），`ZCARD`/`ZRANK` 求分位。避免全量扫描。

#### L2 跨平台

```
freshness = exp( -Δt_hours / τ )            τ = 12h（可配），Δt = now - first_seen_at
breadth   = min(1, log1p(platform_count) / log1p(ref_platform_count))   ref 默认 8

heat_score = 100 × ( w_rank·rank_pct + w_eng·eng_pct + w_fresh·freshness + w_breadth·breadth )
#   Σw = 1；默认值 w = {0.35, 0.25, 0.20, 0.20}
#   某因子缺失时，该权重按比例分配给其余因子（分母取有效权重之和）
```

#### L3 动态

```
EWMA:  h_ewma(t) = α·h(t) + (1-α)·h_ewma(t-1)      α = 0.4（可配）
velocity(t) = ( h_ewma(t) - h_ewma(t-1) ) / Δt_hours        [单位：分/小时]
v_ewma(t)   = β·velocity(t) + (1-β)·v_ewma(t-1)             β = 0.5
accel(t)    = ( v_ewma(t) - v_ewma(t-1) ) / Δt_hours
```

**输出必须包含因子明细**（NFR-TT-05）：

```go
type HeatResult struct {
    Score     float64
    RankPct   float64
    EngPct    float64
    Freshness float64
    Breadth   float64
    Weights   struct{ WRank, WEng, WFresh, WBreath float64 }
    Missing   []string   // 缺失因子列表（决定权重重分配）
}
```

### 2.2 生命周期状态机（`biz/tt/lifecycle.go`）

**判据表**（阈值可配，存 `sys_config` 或 `WeightConfig` 同级配置表）

| 目标阶段 | 判据 | 默认阈值 |
|---------|------|---------|
| `latent` | 采样点 <3 **且** `heat_score < 30` **且** platform_count ≤ 2 | heat<30 |
| `rising` | `velocity > v_min` **且** 持续 ≥2 采样点 | v_min = 6.0 分/小时 |
| `peak` | `heat_score ≥ 80` **或**（`velocity` 由正转负 **且** `heat_score ≥ 60`） | heat≥80 |
| `decaying` | `velocity < 0` 持续 ≥3 采样点 | — |
| `long_tail` | `heat_score < 20` **且** age > 7d **且** 近 24h 仍有更新 | heat<20 |

**防抖动（Hysteresis）** 🔴

阶段切换必须满足**最小驻留时间**，否则会在阈值附近反复跳变：

```
min_dwell = {
  latent:    0,       // 允许快速转出
  rising:    2 点,
  peak:      1 点,
  decaying:  3 点,
  long_tail: 6 点,
}
状态转移前检查： now - stage_since >= min_dwell(current)
```

**状态转移图**

```
        ┌─────────┐
        │ latent  │
        └────┬────┘
    velocity>阈值 │
             ▼
        ┌─────────┐   heat≥80 或 velocity转负   ┌────────┐
        │ rising  │ ─────────────────────────► │  peak  │
        └────┬────┘                            └───┬────┘
             │ velocity<0 持续3点                   │ velocity<0 持续3点
             └──────────────┬─────────────────────┘
                            ▼
                      ┌──────────┐   heat<20 且 age>7d 且仍有更新
                      │ decaying │ ─────────────────────────► ┌───────────┐
                      └────┬─────┘                            │ long_tail │
                           │ 热度回升（velocity>阈值 且 heat>30）  └───────────┘
                           ▼
                      ┌─────────┐
                      │ rising  │  ← 允许「二次爆发」
                      └─────────┘
```

> **注意**：状态机**允许** decaying → rising（二次爆发），这是真实世界常见现象（如事件反转）。

### 2.3 突发检测（`biz/tt/burst.go`）

```go
type BurstDetector interface {
    Detect(ctx context.Context, series []HeatPoint, cfg BurstConfig) BurstResult
}

type BurstResult struct {
    IsBurst     bool
    MethodsHit  []string          // ["zscore","velocity","rank_jump"]
    Evidence    map[string]float64 // {"zscore":4.2, "velocity":0.31, "rank_jump":22}
}
```

#### 方法一：Z-score 残差

```
residual(t) = heat(t) - h_ewma(t)
σ = stddev( residual over last W points )     W = 24（约 12 小时 @30min）
hit_zscore  ⟺  |residual(t)| > k·σ   ∧   σ > σ_min      k = 3, σ_min = 1.0
#   σ_min 防止「序列极平稳时任何微小波动都被判突发」
```

#### 方法二：双阈值增速

```
hit_velocity ⟺ velocity(t) > v_min_burst  ∧  heat(t) > h_min_burst
#   默认 v_min_burst = 8.0 分/小时，h_min_burst = 40
#   h_min 的作用：避免「0 分涨到 5 分」这种低基数噪声被判突发
```

#### 方法三：榜单跃迁

```
hit_ranjump ⟺ ( 首次进榜 ∧ heat(t) > 20 )
             ∨ ( rank(t-N) - rank(t) >= rank_jump_min )      N=1 周期, 默认 10 位
#   首次进榜也需 heat>20，避免长尾话题刚被收录就告警
```

#### 投票

```
IsBurst ⟺ count(methodsHit) >= 2
```

**误报处理**：`Alert.is_false_positive` 标记后，纳入阈值调参样本；提供「按 topic/平台统计误报率」报表。

### 2.4 选题评分（`biz/tt/scoring.go`）

```
hot         = heat_score / 100
freshness   = exp( -age_hours / τ_f )                  τ_f = 24h
workability = IntelItem.workability.score              （来自 IC，0–1）
compliance  = 1.0  if gate == pass
            = 0.5  if gate == review                   （可加工但需人工确认）
            = 0.0  if gate == block                    （**直接不进候选**）

score_total = 100 × ( w_hot·hot + w_freshness·freshness
                      + w_workability·workability + w_compliance·compliance )
#   默认 w = {0.40, 0.25, 0.20, 0.15}
```

**路由判定**

```go
func decideRoute(t *Topic, it *IntelItem) Route {
    toMME := it.Category == A_hot || it.Category == B_material
    toMME  = toMME && it.Workability.Score >= workabilityThreshold  // 默认 0.5
    toMIA := it.Category == C_market
    switch {
    case toMME && toMIA: return RouteBoth
    case toMME:          return RouteMME
    case toMIA:          return RouteMIA
    default:             return RouteNone   // 不产生候选
    }
}
```

**人工干预**：支持置顶（+∞ 排序权重）与降权（×0.5），操作记录审计。

**候选生成时机**：每 15 分钟扫描 `stage ∈ {rising, peak}` 的话题；同一 topic 24 小时内**只产生一个**候选（去重）。

## 5. 错误处理

| 错误码 | 场景 | 处置 |
|--------|------|------|
| `TT_TOPIC_NOT_FOUND` | 话题不存在 | 前端提示 |
| `TT_INFLUX_WRITE_FAIL` | InfluxDB 写入失败 | **落 Redis 缓冲（TTL 1h）** + 告警；后台任务重放 |
| `TT_INFLUX_READ_FAIL` | 查询失败 | 返回降级提示，**禁止**静默返回空（NFR-TT-08） |
| `TT_INSUFFICIENT_POINTS` | 采样点不足无法计算 | 返回 `latent` + 标记 `insufficient=true`，不下结论 |
| `TT_WEIGHT_INVALID` | 权重和不为 1 | 拒绝保存，返回校验错误 |
| `TT_CANDIDATE_ALREADY_ADOPTED` | 重复采纳 | 幂等返回成功 |
| `TT_SUBSCRIPTION_LIMIT` | 订阅数超限 | 返回上限提示 |

**降采样失败**：记录 `tt_downsample_fail_total` 指标，下一周期自动重试（Flux 任务的 range 窗口留 30 分钟重叠，保证补数据不重不漏）。
