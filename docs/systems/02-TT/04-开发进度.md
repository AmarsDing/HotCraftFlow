## 7. 风险与砍单顺序

### 7.1 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 热度权重初期标定不准 | **高** | 中（选题台价值下降） | 因子显式可查 + 配置页 + FR-TRK-13 闭环；**接受初期不准** |
| IC 延期导致 TT 无真实数据 | 中 | 高 | W2–W4 用**回放样本数据**提前验证算法 |
| InfluxDB 本机实例不可复用 | 中 | 中 | 备选 TimescaleDB（PG 扩展）；M0 前必须确认 |
| 生命周期阶段抖动 | 中 | 中 | 最小驻留 + 黄金数据集回归 |
| 突发误报过多导致推送疲劳 | 中 | 中 | 三方法投票 + 静音 + 误报标记调参 |
| 时区处理出错 | 低 | **高**（财经数据错位） | 单一工具函数 + 专项测试覆盖 |

### 7.2 砍单顺序（延期时**自上而下**砍）

```
1. FR-TRK-07 热度看板（降为表格 + 简化曲线）
2. FR-TRK-06 追踪订阅（降为仅支持已存在话题，不做主动采集）
3. FR-TRK-04 生命周期（降为三阶段：rising / peak / decaying）
4. FR-TRK-05 突发检测（降为双方法投票）
5. FR-TRK-03 聚类（降为直接复用 IC cluster_id）
────────── 以下为 🔴 不可砍 ──────────
   FR-TRK-01 热度时序采集
   FR-TRK-02 热度归一化（含因子明细，NFR-TT-05）
   FR-TRK-09 选题评分
   时区纪律（NFR-TT-03）
```

> **说明**：因子明细（NFR-TT-05）不可砍。没有因子明细的热度分是黑箱，出问题无法排查，且违反「分数可解释」的产品承诺。
