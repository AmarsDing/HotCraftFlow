## 1. 目标与边界

> **IC 解决「有什么」，TT 解决「什么在涨、值不值得做、什么时候做」。**

| 项 | 内容 |
|----|------|
| **目标** | 对情报条目做**时间序列化**追踪，识别热度演化、生命周期与突发，输出可排序的选题建议 |
| **输入** | `IntelItem` 流（含各平台排名与互动数快照） |
| **输出** | `TrendSeries` · `TopicCandidate` · `Alert` |
| **上游** | ① IC（全量 `IntelItem`） |
| **下游** | ④ MME（`route=mme`）· ③ MIA（`route=mia`）· 推送渠道 |

### 1.1 明确不做 🔴

| 不做 | 原因 |
|------|------|
| **不承诺预测准确率** | 趋势外推是参考值，须带置信区间并明确标注 |
| **不承诺覆盖全平台** | 依赖 IC 信源覆盖；IC 覆盖不到的平台 TT 无从追踪 |
| **不做舆情定性结论输出** | 「正面/负面舆情」属研判范畴，非本系统职责 |
| **不承诺 `heat_score` 是绝对热度** | 它是**相对可比分数**，跨平台可比性依赖人工标定权重 |
| **不自动采纳选题** | `TopicCandidate.state` 必须经人工或显式规则流转，评分只用于排序 |

## 3. 核心概念（需在需求阶段对齐）

### 3.1 跨平台热度归一化（核心难题）

各平台热度**不可直接比较**——微博热搜榜位、B站播放量、Reddit upvote 是三种完全不同的量纲。三层设计：

| 层 | 指标 | 计算 | 说明 |
|----|------|------|------|
| **L1 平台内** | 排名分位 `rank_pct` | `(rank_total - rank) / rank_total` | 榜首≈1，榜尾≈0 |
| | 互动强度 `eng_rate` | 互动数 / 曝光数；无曝光时退化为**互动量对数分位** | 消除平台体量差异 |
| **L2 跨平台** | 综合热度 `heat_score` (0–100) | `w1·rank_pct + w2·eng_pct + w3·freshness + w4·breadth`（权重和=1） | **相对可比分数** |
| **L3 动态** | 增速 `velocity` | `heat_score` 单位时间变化率（EWMA 平滑） | 判上升 |
| | 加速度 `accel` | `velocity` 变化率 | 判突发 |

> **诚实**：`heat_score` 是**相对可比分数而非绝对热度**。跨平台权重依赖人工标定，UI **必须**明示「分数可解释」且四个因子的实际取值可见（`heat.factors` 字段）。

### 3.2 生命周期模型（五阶段）

| 阶段 | 判据（阈值可配） | 内容策略 |
|------|------------------|----------|
| **Latent 萌芽** | 首次出现，平台数 1–2，`heat_score` < 30 | 观察，蓄稿 |
| **Rising 上升** | `velocity > v_min` **且**持续 ≥2 采样点 | **黄金窗口**，优先加工 |
| **Peak 峰值** | `heat_score ≥ 80` 或 `velocity` 转负前 | 抢发，但竞争激烈 |
| **Decaying 衰退** | `velocity < 0` 持续 ≥3 点 | 仅做长尾解读/合集 |
| **Long-tail 长尾** | 低热度但持续存在 | 素材库沉淀，做常青内容 |

### 3.3 突发检测（三方法投票）

| 方法 | 原理 | 适用 |
|------|------|------|
| **Z-score 残差** | 对 `heat_score` 时序做 EWMA/STL 分解，残差 > `k·σ`（默认 k=3） | 平稳序列突变 |
| **双阈值增速** | `velocity > v_min` **且** `heat_score > h_min` | 通用（避免低基数噪声） |
| **榜单跃迁** | 首次进榜，或单周期排名跃升 ≥ N 位 | 排行榜型数据源 |

> **验收**：**≥2 种方法命中才算突发**；每次告警须附**触发依据**（哪个方法、哪个数值）；误报可人工标记用于调参。

## 4. 功能需求（FR-TRK-\*）

| ID | 名称 | 描述 | 验收标准 | 优先级 |
|----|------|------|----------|--------|
| **FR-TRK-01** | 热度时序采集 | 周期快照各平台排名与互动数写入时序库 | ≥10 源；间隔可配 2–60 分钟 | **P0** |
| **FR-TRK-02** | 热度归一化 | 实现 §3.1 三层指标 | 各因子值可查看；权重可配 | **P0** |
| **FR-TRK-03** | 话题聚类 | 跨平台同一事件聚为一个 topic | 可人工合并/拆分；错误可反馈 | **P0** |
| **FR-TRK-04** | 生命周期判定 | 五阶段自动判定 | 标签可见；阈值可配；**给出判据数值** | **P1** |
| **FR-TRK-05** | 突发检测 | 三方法投票（§3.3） | ≥2 命中才告警；附依据 | **P1** |
| **FR-TRK-06** | 追踪订阅 | 指定话题/关键词持续追踪，自动更新曲线 | 订阅可管理；取消即停止采集 | **P1** |
| **FR-TRK-07** | 热度看板 | 时序曲线 + 阶段标注 + 跨平台对比 | 可看单话题演化；可对比多平台 | **P1** |
| **FR-TRK-08** | 预警推送 | 突发命中推送（Webhook/站内/邮件/企业微信） | 渠道可配；含依据与源链接；可静音 | **P1** |
| **FR-TRK-09** | 选题评分 | 热度 × 时效 × 可加工性 × 合规分 → 排序 | 分数可解释；权重可配；可人工置顶/降权 | **P0** |
| **FR-TRK-10** | 溯源 | 找最早出现的时间/平台/账号，重建传播路径 | 给出首发证据链；路径可导出 | **P2** |
| **FR-TRK-11** | 趋势预测（可选） | 外推未来 1–3 周期热度 | **标注为参考值** + 置信区间；**不承诺准确** | **P2** |
| **FR-TRK-12** | 热点档案 | 已结束话题归档，可回查「某日热点」 | 按日期检索；可复盘 | **P2** |
| **FR-TRK-13** | 表现回流校正 | 用 ⑤ MAP 实际表现校正热度模型权重 | ≥1 平台打通；校正前后可对比 | **P2** |

**P0 共 4 条**（01/02/03/09），构成「TT 可用」最小集。

## 5. 非功能需求（NFR）

| ID | 名称 | 要求 |
|----|------|------|
| **NFR-TT-01** | 时序写入 | 单实例支持 ≥500 点/秒写入；不丢点（JetStream 保证至少一次） |
| **NFR-TT-02** | 查询性能 | 单话题 90 天曲线查询 P95 ≤800ms |
| **NFR-TT-03** | 时区纪律 🔴 | **存储一律 UTC，展示 Asia/Shanghai**。财经跨市场对齐的硬要求 |
| **NFR-TT-04** | 采样纪律 | 热榜源默认 **30 分钟**；**不得高于 newsnow 默认缓存频率**（更高频率无意义且增加上游负载） |
| **NFR-TT-05** | 可解释性 🔴 | 任何分数（heat / stage / burst / candidate）**必须**能追溯到具体因子数值 |
| **NFR-TT-06** | 存储分层 | 原始快照 ≥90 天；聚合曲线 ≥1 年；超期自动降采样 |
| **NFR-TT-07** | 幂等 | 同 `(topic_id, platform, t)` 重复写入覆盖而非追加 |
| **NFR-TT-08** | 降级 | InfluxDB 不可用时，看板降级为「最近 N 点内存态」+ 明确提示，**不静默返回空** |

## 9. 诚实声明

1. **`heat_score` 是相对值不是绝对值**。跨平台权重要靠人工标定，初期标定不准是**预期内**的，需靠 FR-TRK-13 回流校正逐步改善。本需求**不承诺**初期准确率。
2. **采样频率受上游限制**。newsnow 默认缓存 30 分钟，因此热榜源的**有效最小采样间隔就是 30 分钟**。宣称「分钟级热点监控」是不诚实的。
3. **突发检测必然有误报**。三方法投票降低但不消除误报。系统提供「误报标记 → 调参」的闭环，而不是承诺零误报。
4. **趋势预测是参考值**。FR-TRK-11 标注为 P2 且必须带置信区间，**不得**作为决策唯一依据。
5. **选题采纳率 60% 已是较高目标**。选题是主观判断，系统的价值在于**排序与节省筛选时间**，而非替人决策。
