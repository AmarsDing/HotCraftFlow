## 1. 系统上下文

```
① IC ──IntelItem(category=C_market)──┐
                                      ├──► ┌──────────────────────────────────┐
② TT ──TopicCandidate(route=mia)─────┘    │  ③ MIA 市场影响分析系统            │
                                          │                                  │
   OpenBB（股/指数/宏观，只读）────────► │  实体链接 → 情感方向 → 事件聚类     │
   ccxt（加密行情，只读）      ────────► │  → 影响评分(TTL) → 跨资产传导      │
   FinBERT（自托管推理）       ────────► │  → ImpactCard → 行情校验           │
   LLM（中文宏观，可降级）     ────────► │                                  │
                                          └──────┬───────────────┬──────────┘
                                                 │               │
                                          mm.impact.card.v1   简报/推送
                                                 │            （含免责声明）
                                                 ▼
                                          内部看板 / Webhook / 企业微信
```

**边界原则** 🔴

| 原则 | 说明 |
|------|------|
| **只读** | 行情依赖**一律只读**，交易能力配置层硬关闭 |
| **内部优先** | V1 默认**仅内部**输出（待决策 Q2）；对外发布须法务审 |
| **假设非因果** | 跨资产传导结论必须标 `confidence` 与「假设」语义 |
| **不猜** | 情感引擎全不可用时，**不产出方向结论**而非猜一个 |

## 2. 分层架构

```
┌─ L1 接入层  Ingest ────────────────────────────────────────────┐
│  订阅 IntelItem(C_market) 与 TopicCandidate(route=mia)          │
│  双调度入口：股市调度器 / 加密调度器（独立可配，互不阻塞）      │
└──────────────────────────┬────────────────────────────────────┘
                           ▼
┌─ L2 理解层  Comprehend ────────────────────────────────────────┐
│  实体抽取结果 → 实体链接（查映射表 A）                          │
│  情感与方向：FinBERT（英文）/ LLM（中文 + 宏观）                │
│  降级链：FinBERT → LLM → 不产出方向（禁止猜测）                 │
└──────────────────────────┬────────────────────────────────────┘
                           ▼
┌─ L3 聚合层  Aggregate ─────────────────────────────────────────┐
│  事件聚类：多源转载 → EventCard（保留全部来源指针）             │
│  叙事匹配：查映射表 B（加密叙事 → 币种）                        │
└──────────────────────────┬────────────────────────────────────┘
                           ▼
┌─ L4 评分层  Score ─────────────────────────────────────────────┐
│  影响面评分 = 情感 × 源权重 × 相关性 × TTL 衰减                 │
│  跨资产传导规则引擎（每条规则带 confidence）                    │
│  影响路径生成器（每条结论必须有 path）                          │
└──────────────────────────┬────────────────────────────────────┘
                           ▼
┌─ L5 出口与校验层  Deliver & Verify ────────────────────────────┐
│  ImpactCard 生成（**disclaimer 非空校验**）                     │
│  高影响推送（含路径 + 免责声明）                                │
│  行情校验（只读 OHLCV）→ 事后校准报告（不承诺准确率）           │
└────────────────────────────────────────────────────────────────┘
```

## 3. 双调度设计（FR-MIA-10）

股市与加密的市场节奏完全不同，**必须**两套独立调度：

| 调度器 | 市场 | 节奏 | 说明 |
|--------|------|------|------|
| **EquityScheduler** | 全球股市 / 宏观 / 汇市 | 交易时段密集（如 15 分钟）+ **盘后摘要**（收盘后一次性汇总） | 需按交易所时区对齐；休市期降频 |
| **CryptoScheduler** | 数字货币 | 固定短周期（5–15 分钟），7×24 | 无固定休市；TTL 更短（加密叙事衰减快） |

**独立性要求**：两个调度器使用**独立的 asynq 队列与 cron**，一方积压或故障不影响另一方。

**交易所时区表**（初始）：

| 市场 | 时区 | 交易时段（本地） |
|------|------|-----------------|
| A股（SSE/SZSE） | Asia/Shanghai | 09:30–11:30 / 13:00–15:00 |
| 港股（HKEX） | Asia/Hong_Kong | 09:30–12:00 / 13:00–16:00 |
| 美股（NYSE/Nasdaq） | America/New_York | 09:30–16:00 |
| 加密 | — | 7×24 |

> **存储纪律**：全部时间戳存 UTC（NFR-MIA-07）；交易时段配置用 IANA 时区名，不用固定偏移（避免夏令时错误）。

## 4. 模块划分（Go 包结构）

```
apps/server/
  api/media/v1/mia/
    mapping.proto        # 映射表 A / B 的 CRUD 与导入导出
    event.proto          # EventCard
    impact.proto         # ImpactCard、评分、推送、校准
  app/admin/internal/
    biz/mia/
      ingest_usecase.go      # 接入（C_market 情报 + mia 候选）
      entity_link.go         # 实体 → 标的（查映射表 A）
      narrative.go           # 叙事 → 币种（查映射表 B）
      sentiment.go           # 情感引擎编排（FinBERT / LLM / 降级）
      event_cluster.go       # 事件聚类 → EventCard
      impact_scorer.go       # 影响面评分（四因子 + TTL）
      transmission.go        # 跨资产传导规则引擎
      path_explainer.go      # 影响路径文本生成
      verifier.go            # 行情校验与校准报告（P2）
      notifier.go            # 高影响推送
      ports.go               # SentimentEngine / QuoteProvider / MappingRepo 端口
    data/mia/
      mapping_repo.go        # 映射表 A / B
      event_repo.go          # EventCard
      impact_repo.go         # ImpactCard
      quote_openbb.go        # OpenBB 适配器（只读）
      quote_ccxt.go          # ccxt 适配器（Python 侧车或 Go 直连，只读）
      quote_cache.go         # Redis 行情缓存
    service/mia/
    worker/mia/
      equity_sched.go        # 股市调度
      crypto_sched.go        # 加密调度
      verify_job.go          # 事后校验任务
```

### 4.1 职责表

| 模块 | 职责 | 不做 |
|------|------|------|
| `biz/mia/entity_link.go` | 实体 → 标的映射查询与置信度计算 | 不维护映射表数据（那是运营的活） |
| `biz/mia/sentiment.go` | 引擎选择与降级编排 | 不实现模型本身（调外部服务） |
| `biz/mia/impact_scorer.go` | 四因子评分 + TTL | 不做传导推断（交给 `transmission.go`） |
| `biz/mia/transmission.go` | 传导规则匹配，**强制输出 confidence** | 不做因果推断 |
| `data/mia/quote_*.go` | **唯一**行情接触面，只读 | 绝不实现下单/撤单 |

## 5. 关键数据流

### 5.1 主链路

```
IntelItem(C_market) / TopicCandidate(route=mia)
  → ingest（按调度器分流）
     → entity_link：抽取实体 → 查映射表 A → 候选标的 + direction_bias
     → sentiment：
          lang=en → FinBERT（自托管）
          lang=zh 或 宏观类 → LLM（云 + Ollama 降级）
          两者都不可用 → **不产出方向结论**（标记 sentiment=unknown）
     → event_cluster：与近 24h 事件卡比对 → 合并或新建 EventCard
     → narrative：查映射表 B → 补充加密标的
     → impact_scorer：score = 情感 × 源权重 × 相关性 × decay
     → transmission：匹配传导规则 → 补充 affected（带 confidence + path）
     → path_explainer：为每条 affected 生成文本路径
     → **校验 disclaimer 非空**（为空拒绝落库）
     → 落 ImpactCard + 发 mm.impact.card.v1
     → 高分（≥阈值）→ notifier 推送（含路径 + 免责声明）
```

### 5.2 行情校验（FR-MIA-11，P2）

```
ImpactCard 生成时记录：symbol + occurred_at + direction + score
  → verify_job（事件发生后 T+1h / T+24h / T+72h 三个时点）
     → 只读拉取 OHLCV（OpenBB / ccxt）
     → 计算 actual_move = (price(T+n) - price(T)) / price(T)
     → hit = (direction=bullish ∧ actual_move>0) ∨ (direction=bearish ∧ actual_move<0)
     → 回填 ImpactCard.verified
  → 周期性出**校准报告**（按 rule_id 统计命中率）
     → **人工**决定是否调整规则权重（不自动改）
```

> 🔴 **校准报告不等于准确率承诺**。报告须注明样本量、时间窗口、市场状态；小样本结论不得对外表述为「命中率」。

### 5.3 降级路径

| 依赖失效 | 降级 | 说明 |
|---------|------|------|
| FinBERT 服务不可用 | 转 LLM | 英文也走 LLM |
| LLM（云）不可用 | 转 Ollama 本地 | 质量下降但可用 |
| 本地 LLM 也不可用 | **不产出方向结论** | `sentiment.label = unknown`，**禁止**猜 |
| OpenBB 不可用 | 跳过股市行情校验 | 影响分照常产出（评分不依赖行情） |
| ccxt 不可用 | 跳过加密行情校验 | 同上 |
| 映射表无命中 | 该实体**不产生** affected | 诚实返回空，而非强行匹配 |

## 6. 接口契约

### 6.1 NATS

| Subject | 载荷 | 方向 |
|---------|------|------|
| `mm.intel.normalized.v1` | `IntelItem`（过滤 `C_market`） | ← IC |
| `mm.trend.candidate.v1` | `TopicCandidate`（过滤 `route=mia`） | ← TT |
| `mm.impact.card.v1` | `ImpactCard` | → 简报/推送 |

### 6.2 REST（`api/media/v1/mia`）

| 方法 | 路径 | 用途 |
|------|------|------|
| `GET/POST/PATCH/DELETE` | `/api/v1/media/mia/mappings/entity` | 映射表 A CRUD（FR-MIA-01） |
| `POST` | `/api/v1/media/mia/mappings/entity/import` | CSV 导入 |
| `GET` | `/api/v1/media/mia/mappings/entity/export` | CSV 导出 |
| `GET/POST/...` | `/api/v1/media/mia/mappings/narrative` | 映射表 B（FR-MIA-02） |
| `GET` | `/api/v1/media/mia/events` | 事件卡列表 |
| `POST` | `/api/v1/media/mia/events/{id}/split` / `merge` | 人工干预聚类 |
| `GET` | `/api/v1/media/mia/impacts` | ImpactCard 列表（分数/方向/时间筛选） |
| `GET` | `/api/v1/media/mia/impacts/{id}` | 详情（含路径 + 因子 + 置信度） |
| `GET` | `/api/v1/media/mia/impacts/{id}/verify` | 行情校验结果 |
| `GET` | `/api/v1/media/mia/calibration` | 校准报告（P2） |
| `GET` | `/api/v1/media/mia/rules` | 传导规则查看（含 confidence） |
| `GET` | `/api/v1/media/mia/quotes/{symbol}` | 行情只读查询 |

### 6.3 前端页面（Quasar）

| 路由 | 页面 | 内容 |
|------|------|------|
| `/media/mia/impacts` | **影响卡列表** | 按分数/时间排序、方向标记、**TTL 剩余时间** |
| `/media/mia/impacts/{id}` | 影响卡详情 | 事件摘要、关联标的（含 confidence + path）、四因子面板、**免责声明** |
| `/media/mia/events` | 事件卡 | 聚类结果、来源指针、人工拆分/合并 |
| `/media/mia/mappings` | 映射表管理 | 表 A/B 的 CRUD + CSV 导入导出 |
| `/media/mia/calibration` | 校准报告 | 按规则统计（P2） |

**UI 强制要求** 🔴：
- 每页**固定展示**免责声明（不可折叠关闭）
- 每条 affected 项必须显示 `confidence` 与「假设非因果」提示
- 无 `path` 的结论**不得**渲染为结论（降级为「待分析」）

## 7. 关键技术决策（ADR 摘要）

| # | 决策 | 备选 | 理由 |
|---|------|------|------|
| **ADR-MIA-01** | 情感引擎 **FinBERT（英）+ LLM（中/宏观）双轨** | 单一模型 | FinBERT 英文财经强且可自托管；中文无同等开源，只能靠 LLM |
| **ADR-MIA-02** | 引擎全不可用时**不产出方向**，而非猜测 | 规则兜底猜一个 | NFR-MIA-08；猜测的市场结论风险远高于「不知道」 |
| **ADR-MIA-03** | 行情依赖**只读**，配置层硬关闭交易 | 完整接入 ccxt | NFR-19③；交易能力一旦启用，责任边界失控 |
| **ADR-MIA-04** | 影响分**带 TTL** | 永久有效 | 旧利好长期占榜会让看板失真（PRD §5.7④） |
| **ADR-MIA-05** | 传导规则**每条带 confidence** | 规则即结论 | 跨资产传导是假设不是因果（NFR-MIA-03） |
| **ADR-MIA-06** | 股市/加密**双调度独立队列** | 统一调度 | 节奏差异大（交易时段 vs 7×24），统一调度会互相拖累 |
| **ADR-MIA-07** | 校准**出建议不自动改权重** | 自动调权重 | 同 TT：自动改会造成历史口径漂移，不可复算 |
| **ADR-MIA-08** | 映射表**人工可维护 + CSV 导入导出** | 硬编码 | 映射表是长期运营资产，必须非技术可维护 |
| **ADR-MIA-09** | OpenBB 标 `[待核实]`，**不预先依赖** | 直接采用 | 许可证未确认，引入前必须复核（NFR-19①） |

## 8. 容量与性能估算（V1 单实例）

| 项 | 估算 |
|----|------|
| 日处理 C_market 情报 | 300–1,500 条 |
| 日产 EventCard | 80–300 张 |
| 日产 ImpactCard | 80–300 张 |
| FinBERT 推理 | 自托管，单条约 20–50ms（GPU）/ 200–500ms（CPU） |
| 云 LLM 调用 | 日均 ≤500 次（成本帽） |
| 行情查询 | 只读 OHLCV，Redis 缓存 5 分钟 |
| 推送 | 高分条目日均 ≤20 条 |

## 9. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| **被误读为投资建议** | 中 | **极高** | 免责声明强制非空 + UI 固定展示 + 置信度必显 + V1 仅内部 |
| 映射表覆盖不足 | **高** | 高（漏判/误判） | 初始 200/30 条为起点；CSV 导入；人工补录闭环 |
| 中文情感质量不佳 | 中 | 中 | LLM + 人工复核；不承诺准确率 |
| OpenBB 许可证风险 | 中 | 中 | 引入前强制复核；备选直连 Yahoo/Alpha Vantage 等 |
| 加密叙事噪声 | **高** | 中 | 事件聚类前置（多源合并才打分），避免单条噪声直接出方向 |
| 云 LLM 成本失控 | 中 | 中 | 总量帽硬熔断 + 本地 Ollama 降级 |
| 行情数据源 ToS 变化 | 中 | 中 | NFR-19② 书面确认 + 多源冗余 |

## 10. 与其他子系统的接口约定

| 对 | 约定 |
|----|------|
| ← **① IC** | 消费 `category=C_market` 的 `IntelItem`。依赖 `entities`（`confidence ≥0.6`）做实体链接 |
| ← **② TT** | 消费 `route=mia` 的 `TopicCandidate`。依赖 `topic_id` 关联 `ImpactCard` |
| → 推送 | 发 `ImpactCard`，**必须**含 `disclaimer`、`affected[].path`、`affected[].confidence` |
| → **④ MME** | **不直连**。MIA 是分析结论，MME 是可发布内容，二者不得混为同一按钮（PRD §1.2） |

**纪律** 🔴：MIA 的结论**不得**直接作为 MME 的发布素材。若要对外传播，必须经二次创作 + 法务审核。
