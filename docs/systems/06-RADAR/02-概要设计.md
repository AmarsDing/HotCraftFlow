## 1. 系统上下文

```
                        ┌──────────────────────────────────────┐
  github.com/trending ─►│                                      │
  api.github.com ──────►│        ⑥ RADAR（FrameWork 壳内）      │
  OpenAI 兼容 LLM ─────►│                                      │
                        └───────────────┬──────────────────────┘
                                        │ REST /api/v1/radar/*
                        ┌───────────────▼──────────────────────┐
                        │  平台登录用户（Quasar /github-radar）  │
                        │  · 榜单/新星  · 详情/AI/源码/克隆       │
                        │  · 个人盯盘   · 变更通知                │
                        └──────────────────────────────────────┘
            平台管理员 ─► PUT /api/v1/radar/config（Token/LLM/克隆）
```

**边界原则**：
- RADAR **只读 GitHub**，不写 GitHub；**只消费**外部数据，不向媒体矩阵主干（IC→MAP）供数。
- 榜单是**查询态**（缓存+快照），盯盘/配置是**持久态**（三张 DB 表）——两条数据通路互不混淆。
- 与平台的关系：复用 JWT 鉴权、用户体系、菜单/路由、通知交互范式、AES 加密与 retention 基建；**不复用**平台站内信表（通知=盯盘事件视图，见 ADR-RAD-04）。

## 2. 分层架构（Kratos 标准四层 + worker）

```
┌─ transport 层 ──────────────────────────────────────────────┐
│  rest.go 注册 5 个 radar 服务的 HTTP（buf 生成 handler）       │
├─ service 层（proto 实现 + 鉴权 + DTO 映射）──────────────────┤
│  radar_trending_service / radar_repo_service                 │
│  radar_watch_service    / radar_notify_service               │
│  radar_config_service（兼 biz.RadarConfigProvider 实现）      │
├─ biz 层（领域逻辑，对外的唯一智力层）─────────────────────────┤
│  RadarTrendingUsecase ─ RadarTrendingReader（端口）           │
│    └ GitHubRadarTrendingReader（真实源）/ DemoReader（演示）  │
│  GitHubClient（缓存/重试/快照/频控的聚合出口）                │
│  RadarRepoUsecase · InsightService · RadarConfigUsecase      │
│  RadarWatchUsecase · RadarNotifyUsecase                      │
├─ data 层（仓储实现 + ent）──────────────────────────────────┤
│  RadarWatchRepo / RadarWatchEventRepo / RadarUserConfigRepo  │
│  （user_id 行级强制过滤；密钥字段 AES-256-GCM 加解密）        │
├─ worker ────────────────────────────────────────────────────┤
│  RadarEventRetentionWorker（30 天物理清理 cron）              │
└──────────────────────────────────────────────────────────────┘
```

**只有一个外部接触面**：`GitHubClient`。任何对 github.com / api.github.com 的请求都从它出——缓存、重试、快照、超时、UA 全在这一层收口。

## 3. 模块划分与落位

### 3.1 后端（`apps/server`）

```
api/radar/v1/
  trending.proto   # 热门榜 + 新星搜索（RepoItem 通用视图）
  repo.proto       # 详情 / 文件树 / 文件内容 / 克隆 / AIInsight
  watch.proto      # 盯盘 + 盯盘事件
  notify.proto     # 雷达通知（=盯盘事件视图）
  config.proto     # 平台配置（Token/LLM/克隆，脱敏回显）
app/admin/internal/
  biz/
    radar_github_client.go   # ★ 外部接触面：双引擎+缓存+快照+频控
    radar_trending.go        # 榜单编排：enrich 补全 → finalize 过滤/排序/分页
    radar_repo.go            # 详情/树/内容/克隆编排 + full_name 校验
    radar_insight.go         # LLM 客户端 + 三级 Prompt + 缓存/频控
    radar_user_data.go       # 盯盘/事件/通知用例 + 仓储端口
    radar_config.go          # 平台配置用例（单行 user_id=0）
    radar_demo.go            # RADAR_DEMO=1 演示数据源
  service/  radar_{trending,repo,watch,notify,config}_service.go
  data/
    ent/schema/ radar_watch.go / radar_watch_event.go / radar_user_config.go
    radar_{watch,watch_event,user_config}_repo.go
  worker/   radar_event_retention_worker.go
```

### 3.2 前端（`apps/web`）

```
src/pages/github-radar/
  RadarPage.vue             # 主页面：筛选栏 + KPI 条 + 榜单网格 + 盯盘侧栏
  types.ts                  # 本地 DTO + 展示工具（langColor/relTime/abbrevCount…）
  components/
    RepoCard.vue            # 榜单卡片（GitHub 官网密度 / a11y / topics 折叠）
    WatchRail.vue           # 盯盘侧栏（宽屏常驻 / 窄屏抽屉；行点击开详情、事件单条已读）
    RepoDetailPanel.vue     # 详情双栏：概览 / AI 分析 / 源码 / 克隆（克隆三址并入此；CloneDialog 已删）
    RepoInsight.vue         # AI 三级总结（cache-only 快照预取秒显）
    SourceBrowser.vue       # 真递归文件树 + 内容浏览（分支可切换）
    Sparkline.vue           # 星标增量迷你曲线（单值退化圆点）
src/components/MarkdownRenderer.vue     # 共享 MD 渲染器（README/AI 统一；链接/图片白名单 + 表格 + 引用合并；MarkdownView 已删）
src/services/kratos/radar/service/v1/   # buf 生成客户端（禁手改）
```

### 3.3 职责表

| 模块 | 职责 | 不做 |
|------|------|------|
| `GitHubClient` | 对 GitHub 的**唯一**出口：请求、退避、TTL 缓存、快照、AI 频控计数、git clone | 不做业务判断（过滤/排序在 reader 的 finalize） |
| `GitHubRadarTrendingReader` | 榜单语义：双引擎→并发补全→过滤排序分页→KPI 统计 | 不直接发 HTTP（全走 client） |
| `InsightService` | 三级 Prompt 构造、LLM 调用、24h 缓存、频控拦截 | 不取数（repo/README 从 client 拿） |
| `RadarWatchService`（service 层） | JWT 取 user_id；列表时触发节流同步星标 | 不做周期任务（同步是 on-read，见 ADR-RAD-03） |
| `RadarConfigService` | 配置读写 + 管理员门禁 + 脱敏；兼 `RadarConfigProvider`（30s 快照缓存喂给 client/insight） | 不落明文、不回显明文 |
| `RadarEventRetentionWorker` | 每日 04:41 删除 30 天前事件 | 不保证 200 条上限（由写入路径 CreateBatch 保证） |
| `RadarPage.vue` | 交互编排：竞态防护（`loadBoardSeq`）、双模式五 API 数据汇合 | 不直连 GitHub、不携带密钥 |

## 4. 关键数据流

### 4.1 榜单查询（FR-RAD-01）

```
GET /trending?since&language&...
  → service → usecase → reader.ListLatest
     → cacheGet("trending:since|language") 命中即返（10min TTL）
     → GitHubClient.FetchTrending
        ├─ 引擎A：trending HTML 正则解析（唯一带官方窗口增量的途径）
        └─ 引擎B：Search API created:>窗口 兜底（无增量字段）
        失败 → loadSnapshot → 200 + stale=true + 截断原因
     → enrichEntries：并发 4 / 上限 25 仓补详情（语言构成/贡献者/License）
        单仓失败保留 HTML 基础字段；差分上一快照生成 sparkline
     → saveSnapshot + cacheSet
     → finalize：语言/Topic/License/only_new/query 过滤
        → hot|stars|updated|new 排序 → 分页 → rank 回填
        → language_top / license_top（窗口级分布，不受筛选影响）
        → rising_count / new_count / total（过滤后口径）
```

### 4.2 盯盘星标同步（FR-RAD-09，on-read 非 cron）

```
GET /watches（用户打开页面触发）
  → uc.List → service.syncStars
     → 过滤：距上次更新 <10min 跳过；单次最多 12 个盯盘；并发 4
     → 逐仓 GetRepoDetail（命中 30min 缓存则零外呼）
     → uc.SyncStars：刷新 stars/delta/sparkline
        相对上次记录新增 ≥50 星 → 写 STARS 事件 + 重算未读数
  → 重读列表回显（可能产生的新未读已计入）
```

> **设计意图**：盯盘同步惰性触发（谁看谁刷），不做全局 cron 轮询——盯盘总数未知时，cron 会把 GitHub 限额烧在无人在看的仓库上。10min 节流 + 12 上限保护限额。

### 4.3 AI 总结（FR-RAD-05）

```
POST /insight {full_name, level}
  → 校验 level ∈ {brief,summary,deep}
  → config.RadarLLM() 未启用 → 返回引导文案（不报错）
  → cacheGet("insight:full:level") 命中 → cached=true 即返（24h）
  → allowInsightGen：每(仓,级)/日 ≤3，超限 → 文案拦截
  → GetRepoDetail + GetReadme（截断 8000 字、去徽章/HTML 噪声）
  → buildInsightPrompt（三级固定小节模板 + 元数据块）
  → OpenAI 兼容 chat/completions（temperature 0.3，max_tokens 120/700/1400，60s 超时）
  → 缓存 24h，回显 model/generated_at/duration_ms
```

### 4.4 平台配置（FR-RAD-11）

```
PUT /config（仅 SYS_ADMIN / TENANT_ADMIN）
  → service trim → biz 归一化（空串=保留原值；LLM 空值落默认 openai/gpt-4o-mini）
  → repo.Save：AES-256-GCM 加密 token/api_key 后 upsert 单行（user_id=0）
  → 失效 30s 快照缓存 → 脱敏回显（abcd…wxyz）

GitHubClient/InsightService 取配置：
  → RadarConfigService.GitHubToken()/RadarLLM()/CloneSettings()（30s 内存快照，避免每请求读库）
```

## 5. 外部依赖与部署形态

| 依赖 | 形态 | 失败影响 | 回退/降级 |
|------|------|---------|----------|
| `github.com/trending`（HTML） | 公网 HTTP | 官方窗口增量不可得 | Search API 兜底（无增量口径） |
| `api.github.com` REST | 公网 HTTP，Bearer Token | 榜单/详情全部失效 | stale 快照 + `stale_reason` 展示 |
| OpenAI 兼容 LLM | 公网/内网 HTTP | 仅 AI 功能 | 未配置时的引导文案；错误入 `AIInsight.error` 不回 500 |
| `git` CLI | 本机进程 | 仅服务端克隆 | 克隆三址仍返回（`to_server=false` 不受影响） |
| PostgreSQL 5434 | 基础设施 | 盯盘/配置不可读写 | 无（强依赖；榜单不受影响） |
| `RADAR_DEMO=1` | 环境变量 | — | 无外网环境演示数据源（禁生产） |

> **与原独立版的差异**：独立 `github-radar` 前后端进程已下线；只保留 FrameWork 启动方式（迁移计划 P5）。端口/库表全部并入 admin 进程与平台库。

## 6. 接口契约

### 6.1 REST（`package radar.service.v1`，buf managed codegen）

| 方法 | 路径 | 服务 | 鉴权 |
|------|------|------|------|
| `GET` | `/api/v1/radar/trending` | TrendingService.ListTrending | 登录 |
| `GET` | `/api/v1/radar/rising` | TrendingService.SearchRising | 登录 |
| `GET` | `/api/v1/radar/repo` | RepoService.GetRepo（`include_readme`/`insight_level` 可叠加；`insight_cache_only=true` 走只读快照，见 ADR-RAD-10） | 登录 |
| `GET` | `/api/v1/radar/repo/tree` | RepoService.GetRepoTree | 登录 |
| `GET` | `/api/v1/radar/repo/content` | RepoService.GetRepoContent | 登录 |
| `POST` | `/api/v1/radar/repo/clone` | RepoService.CloneRepo | 登录（服务端克隆另受配置开关约束） |
| `POST` | `/api/v1/radar/insight` | RepoService.GenerateInsight | 登录 |
| `GET/POST/DELETE` | `/api/v1/radar/watches[/{id}]` | WatchService | 登录（行级隔离） |
| `GET` `/api/v1/radar/watch-events` · `POST .../read` | WatchService | 登录（行级隔离） |
| `GET` `/api/v1/radar/notifications` · `POST .../read` | RadarNotifyService | 登录（行级隔离） |
| `GET/PUT` | `/api/v1/radar/config` | RadarConfigService | 读=登录 / **写=管理员** |

> 命名纪律：雷达通知/配置服务显式带 `Radar` 前缀（`RadarNotifyService`/`RadarConfigService`），避免与平台 `NotifyService`/`UserService` 重名冲突。

## 7. 关键技术决策（ADR 摘要）

| # | 决策 | 备选 | 选择理由 |
|---|------|------|---------|
| **ADR-RAD-01** | trending **双引擎**：HTML 优先、Search API 兜底 | 只用 Search API / 只用 HTML | 官方「窗口增量」只在 trending 页；Search API 更稳但无该口径。两者互补，谁也替代不了谁 |
| **ADR-RAD-02** | 失败降级为 **200 + stale 快照**，不抛 500 | 直接透传错误 | 情报工具的「旧数据」价值远高于「报错页」；`stale_reason` 截断防注入与超长 |
| **ADR-RAD-03** | 盯盘星标同步 **on-read + 节流**，不做全局 cron | asynq 周期轮询 | 无人在看时不烧 GitHub 限额；10min/12 上限/并发 4 三保险 |
| **ADR-RAD-04** | 雷达通知 **= 盯盘事件视图**，不建新表 | 接入平台站内信表 | 消除双写与一致性负担；平台站内信面向「系统→人」广播，语义不同 |
| **ADR-RAD-05** | 配置**平台级单行**（user_id=0 sentinel），读=登录、写=管理员 | 每用户一份 | 修复独立版「多用户 token 互相覆盖/泄露」缺陷；ent schema 保留 user_id 列以兼容未来按用户隔离 |
| **ADR-RAD-06** | 缓存/快照/频控计数全部**进程内存**，不进 Redis | Redis 共享缓存 | 单实例部署下零额外运维；重启即冷启属可接受代价（榜单 10min 即回暖） |
| **ADR-RAD-07** | AI 总结**三档固定模板** + 缓存 24h + 每日 3 次频控 | 自由提问 / 实时生成 | 成本与体验平衡：情报速览场景 90% 是同一批阅读意图；硬频控防刷 |
| **ADR-RAD-08** | 服务端克隆**默认关**、`--depth 1`、60s 超时、目录复用 | 默认开 / 全量 clone | 磁盘与安全的最小攻击面；`full_name` 严格校验后拼路径 |
| **ADR-RAD-09** | 前端**单页多面板**而非多路由 | 详情独立路由页 | 雷达场景高频「扫榜→点开→关」，抽屉式往返成本最低；组件全部走平台 token（迁移计划验收项） |
| **ADR-RAD-10** | AI 快照预取走 **cache-only 只读通道**（`InsightService.GetCached`，复制返回不改写共享缓存），详情打开不触发任何生成/频控 | 预取即生成 / 不预取 | 秒显与配额纪律兼得：命中＝零等待零消耗；未命中＝面板原样「生成」CTA |
| **ADR-RAD-11** | 前端响应**单点归一化**（`types.ts` 的 `normalize*`，camel/snake 双键兜底集中一处），组件只读本地 snake_case DTO | 各组件各自兼容字段 | 修复「详情元数据/AI 正文整体渲染为空」的根因层；字段错配 bug 类整体消除 |

## 8. 容量与性能估算（单实例）

| 项 | 估算 |
|----|------|
| 榜单缓存键 | `since(3) × 常用语言(≈10)` ≈ 30 键 × ≤50 仓 ≈ 万级字段内存，可忽略 |
| GitHub 调用量（配有 Token） | 榜单 10min 周期 ≈ 6 次/小时/窗口语言组合；详情 30min 缓存复用；远低于 5000 次/小时限额 |
| 盯盘 | 单用户 ≤50 仓假设；列表触发 ≤12 仓/10min ⇒ 单用户 ≤72 次/小时外呼上界 |
| AI | 每仓每级每日 ≤3 次 × 1400 tokens 封顶 ⇒ 成本有硬上界 |
| DB | 三张表行数有界：config 单行；watch ≤ 用户×盯盘数；event ≤ 用户×200（另有 30 天清理） |

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| GitHub trending 页改版 | 官方增量口径失效 | 双引擎兜底 + 解析零命中即报警错误（`no <article> parsed`），可快速发现 |
| 匿名/单 Token 限额耗尽 | 抓取大面积失败 | 多层 TTL 缓存 + 退避 + stale 兜底；设置页强提示必须配 Token |
| LLM 费用/不可用 | AI 功能异常 | 默认关；频控+缓存；错误内嵌响应不阻断详情 |
| 服务端克隆撑爆磁盘 | 磁盘耗尽 | 默认关 + depth 1 + 已存在复用；目录由管理员单点控制 |
| 解密失败（密钥轮换等） | 配置密钥读不出 | 按空值处理并记 error 日志，不阻断非密钥字段 |
| 事件表膨胀 | 慢查询 | 写入裁剪 200/人 + cron 30 天物理删 + (user_id,read)/(user_id,full_name) 索引 |

## 10. 与媒体矩阵五子系统的关系

| 关系 | 约定 |
|------|------|
| 数据主干 | **不接入**：RADAR 不产出 `IntelItem` 等七份契约消息，不占用 NATS subject |
| 未来可选联动 | IC 若需「GitHub 开源热点」信源，应以**新采集器**调本模块 biz 层端口（`RadarTrendingReader`）或直接调 GitHubClient，**不得**读 radar_* DB 表、不得复用榜单内存缓存语义 |
| 共享基建 | JWT/菜单/i18n/`pkg/crypto`/`pkg/retention` 与平台一致；proto 独立 package（`radar.service.v1`），HTTP 前缀 `/api/v1/radar/`（不占 `/api/v1/media/`） |
