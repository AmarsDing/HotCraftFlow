## 2. Ent Schema（三张表，`data/ent/schema/radar_*.go`）

三张表统一：`utf8mb4/utf8mb4_bin` + `WithComments`；Mixin=`AutoIncrementId{} + Time{}`；Policy=AlwaysAllow 占位（**行级隔离不靠 ent privacy，靠 repo 强制 `user_id` 条件**）。

## 3. biz 层设计

### 3.1 `GitHubClient`（radar_github_client.go）— 唯一外部接触面

**常量**（全部收口在文件头）：

```go
trendingCacheTTL=10m  repoCacheTTL=30m  readmeCacheTTL=60m  treeCacheTTL=10m  contentCacheTTL=10m
trendingEnrichConcurrency=4  trendingEnrichLimit=25
treeTruncateLimit=1000  contentTruncateLimit=512KB  readmeTruncateLimit=200KB  cloneTimeout=60s
http.Client.Timeout=15s  UA="FrameWork-Radar/1.0"
```

| 机制 | 实现要点 |
|------|---------|
| **doJSON 重试** | ≤3 次；403/429 视作限流，退避 1s/2s；body 限读 8MB；≥400 即错（含截断响应体 200 字） |
| **TTL 缓存** | `map[string]cacheEntry{v,exp}` + RWMutex；key 前缀 `trending:/rising:/repo:/readme:/tree:/content:/insight:` |
| **快照** | `snapshots[key(since|language)]` 存最近一次成功的 `[]RadarRepoView`；仅内存，重启清空 |
| **AI 频控** | `genCount["full|level"]`，按 UTC 日翻页清零，每键 ≤3/日 |
| **FetchTrending** | HTML 引擎优先 → 零结果/失败走 Search API；两引擎错误合并返回 |
| **CloneRepo** | `full_name` 已经 biz 校验；`/→__` 拼目录；已存在直接复用；`git clone --depth 1` + `exec.CommandContext`（60s 超时杀进程） |

**HTML 引擎**（fetchTrendingHTML）：8 条预编译正则抽取 `<article>` 块：仓库名（`href="//owner/repo"`，排除 login）、描述、语言（`itemprop="programmingLanguage"`）、总星/Forks（`\d+[kKmM,]?` 解析 `parseGhCount`）、**窗口增量**（`([\d,]+) stars? (today|this week|this month)`）、Top8 贡献者头像 `alt="@login"`。零 `article` 即判定「结构改版」报错。

**Search 兜底**（fetchTrendingSearch）：`q=created:>窗口起点 [language:X]&sort=stars&per_page=50`。注意 **stars_delta=0**。

### 3.2 `GitHubRadarTrendingReader`（radar_trending.go）— 榜单语义

`ListLatest` 链路：`cacheGet → FetchTrending → enrichEntries → saveSnapshot+cacheSet → finalize`。

**enrichEntries**：对前 25 仓并发（信号量 4）调 `GetRepoDetail` 补全；与上一快照差分得 sparkline（`appendSparkline` 保 7 点）；`created_at > windowStart(since)` 标 `is_new`；detail 缺失字段用 HTML 基础字段回填（增量只有 HTML 有，恒以 HTML 为准覆盖）。

**finalize**（纯函数，缓存命中也走）：

1. 全量遍历统计 `language_top`/`license_top`（**窗口级分布，先于筛选计算**，驱动前端下拉选项）；
2. 过滤：language(EqualFold) / topic(EqualFold 逐项) / license(EqualFold SPDX) / only_new / query（full_name+description+topics 小写 contains）；
3. 过滤后统计 `rising_count(stars_delta>0)`、`new_count`、`total`；
4. 排序：`hot`(delta desc 默认) / `stars` / `updated`(pushed_at desc) / `new`(is_new 优先, delta 次)；`sort.SliceStable` 保序；
5. 分页：`page<1→1`；`size∉[1,100]→25`；切片后回填 `rank=start+i+1`。

`SearchRising`：固定 week 窗口、hot 排序，独立缓存键 `rising|language`，finalize 复用。

### 3.3 盯盘用例（radar_user_data.go）

- **`normalizeFullName`**：trim → 必须含 `/` → 总长 ≤200、owner ≤39、repo ≤100 → 正则 `^[A-Za-z0-9](?:[A-Za-z0-9._-]*[A-Za-z0-9])?/[A-Za-z0-9](?:[A-Za-z0-9._-]*[A-Za-z0-9])?$`（Go 不支持前瞻，用等价非前瞻写法 + 长度另行校验）。失败返回 400。
- **`RadarWatchUsecase.Add`**：先查已存在→幂等返回；否则 `Upsert(baseline=0)`（基线在首次同步时落实）。
- **`SyncStars(userID, fullName, stars, sparkline, threshold)`**：更新快照；`grown = (stars−baseline) − 上次记录delta`，`grown ≥ threshold(50)` 才写事件 + 重算未读。threshold ≤0 关闭事件生成。
- **`MarkEventsRead`**：空 ids 返回 400（防误全清）；成功后 `recountUnread` 全量重算各仓未读（失败仅 warn，不阻断）。
- **`RadarNotifyUsecase`**：包在 eventRepo 上的薄壳——通知 = 事件视图（消除独立通知表）。
- 常量：`RadarSystemUserID=0`、`RadarMaxWatchEventsPerUser=200`。

### 3.4 `InsightService`（radar_insight.go）

- `complete()`：OpenAI 兼容 `POST {base}/chat/completions`；base 自动补 `/v1`；`temperature=0.3`；60s 超时；模型空→`gpt-4o-mini`。
- `Generate()` 顺序：**校验 level → 未启用 LLM 返回引导文案 → 24h 缓存命中返 cached → 频控 → 取 repo+README → Prompt → 调 LLM → 缓存**。LLM 错误写入 `AIInsight.error` 返回 200（不抛 RPC 错误）。
- `GetCached(fullName, level)`：**只读** 24h 内存缓存（复制返回值再置 `cached=true`，不改写共享缓存对象），绝不触发生成/频控——专供详情面板打开时的 summary 快照预取（`insight_cache_only` 标记走此路）。
- `buildInsightPrompt` 三级模板（系统人设：资深开源生态分析师，简体中文，不编造）：
  - brief：一句话 ≤50 字，max_tokens 120；
  - summary：五节「是什么/技术栈/核心亮点/适用场景/热度信号」，200-400 字，700；
  - deep：五节「架构与设计推测/优势/风险与局限/社区健康度/上手建议」，500-900 字，1400。
- README 处理：`stripMarkdownNoise` 去 `![`/`<img`/`<a`/`<p>`/`---` 等行，按 rune 截断 8000 字；元数据块含 stars/delta/forks/issues/watchers/license/语言构成 Top5。

### 3.5 `RadarConfigUsecase`（radar_config.go）

平台级单行（userID=0）；`Get` 未配置返回非 nil 空结构；`Set` 语义：**token/api_key 传空串=保留原值**，其余字段全量覆盖；biz 层统一 trim + LLM 空值落默认（service 层也 trim 一次，biz 收口保证任何入口一致）。

## 6. 前端设计（`pages/github-radar/`）

### 6.1 状态与数据流（RadarPage.vue 914 行）

- **双模式**：`mode=trending`（全筛选+KPI）/ `rising`（仅 query+language）。
- **加载**：`loadBoard()` 序号护栏 `loadBoardSeq`（快速切筛选只采纳最后响应）；筛选 watcher 统一先归 `page=1` 再触发（防双请求）；`loadSide()` 并发四请求（watches/events/notifications/config）且**容错静默**（侧栏可降级）。
- **统一归一化层（v1.1）**：kratos 生成 TS 客户端实际返回 **camelCase**，本地 DTO 统一 snake_case——全模块经 `types.ts` 单点函数 `normalizeRepo/normalizeWatch/normalizeWatchEvent/normalizeNotification/normalizeInsight` 转换（`snake ?? camel` 双键兜底），组件不再各自读原始响应（消除「详情元数据/AI 正文整体渲染为空」的字段错配 bug 类）。
- **盯盘开关 toggle（v1.1）**：`watchIdByName`（`Map<full_name,id>`）+ `onWatch` 有 id 即删、无则加——卡片与详情面板书签按钮共用同一 `watch` emit，取消盯盘**零后端改动**（复用既有 `WatchItem.id`）。
- **AI 快照预取（v1.1）**：详情打开时 `GetRepo(insight_level=summary, insight_cache_only=true)` 顺带带出 24h 缓存快照，命中即注入 `RepoInsight.prefetched` 秒显；未命中静默为 null（不消耗生成配额）；用户手动「生成」的新结果按档覆盖种子。
- **侧栏加载与过滤（v1.1）**：`sideLoading` 驱动 WatchRail 骨架（`loading` prop）；事件「仅未读」toggle（`listEvents(unreadOnly)` 增量重取）；页面刷新按钮挂 `loading || sideLoading`。
- **窄屏下拉刷新（v1.1）**：主区由 `:is` 动态组件包裹——窄屏 `QPullToRefresh`（回调等主榜+侧栏双落地），宽屏降级为纯 `div`，避免复制整个主区块。
- **KPI 口径**：优先取后端 `total/new_count/rising_count`（窗口级），缺字段时回退当前页计算。
- **已读联动**：盯盘事件 markAllRead 后同时置 read：events + notifications 两视图；后端拒绝空 ids，故前端先过滤出未读 id 列表。

## 8. 错误处理与降级矩阵

| 场景 | 行为 | 用户可见 |
|------|------|---------|

| 文件树/文件内容加载失败（v1.1） | `treeError`/`contentError` 内嵌 banner + 重试（弃 Notify-only） | 源码页错误横幅 |
| AI 生成接口 5xx（v1.1） | `apiError` 内嵌 banner + 重试（面板内单通道，弃 Notify 双通道） | AI 面板错误横幅 |

| 文件树 1000 节点截断 | `treeTruncated` 提示横幅 | 源码页截断提示 |
| LLM 未配置 | 200 + `error=引导文案` | AI 面板显示配置引导 |
| LLM 调用失败/限流 | 200 + `error=具体错误` | AI 面板错误文案 |
| AI 生成超频 | 200 + `error=已达上限（3 次）` | 频控提示 |
| 解密失败 | 该密钥按空值 + error 日志 | 表现为「未配置」 |
| 盯盘同步部分失败 | warn 日志，列表正常 | 该仓数据略旧 |
