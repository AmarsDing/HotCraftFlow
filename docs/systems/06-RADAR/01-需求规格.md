# ⑥ RADAR GitHub 热点分析系统 · 需求规格

> **子系统**：RADAR · GitHub Hotspot Analysis · GitHub 热点分析（菜单名「github热门追踪」）
> **版本**：v1.0 · **日期**：2026-10-18
> **上游**：迁移计划 [`../../guides/github-radar-port-plan.md`](../../guides/github-radar-port-plan.md) · 契约 `apps/server/api/radar/v1/*.proto`
> **性质说明**：本模块**不属于**媒体矩阵五子系统主干（IC→TT→MIA→MME→MAP），是独立 GitHub 开源情报工具迁入 FrameWork 壳的**已建成模块**。本文按「已实现态」如实描述（as-built），与①~⑤的「目标态」文档口径不同：需求即现状，待办见 [`04-开发进度.md`](./04-开发进度.md)。
> **作者**：架构 · **状态**：已落地

## 1. 目标与边界

| 项 | 内容 |
|----|------|
| **目标** | 在 FrameWork 平台内提供 GitHub 开源热点的一站式追踪：热门榜 / 新星搜索 → 仓库详情 → AI 解读 → 源码速览 → 一键克隆 → 个人盯盘与变更通知 |
| **输入** | GitHub 公共数据（trending 页 HTML + REST API）；平台管理员配置（GitHub Token / LLM / 克隆目录）；当前登录用户的盯盘操作 |
| **输出** | 榜单视图 `RepoItem`、详情 + README + `AIInsight`、文件树/文件内容、克隆指令、盯盘 `WatchItem` 与变更事件 `WatchEvent`、雷达通知 |
| **用户** | 平台全体登录用户（读）+ 系统/租户管理员（写平台配置） |
| **上游依赖** | GitHub 公网可达；可选 OpenAI 兼容 LLM 服务；可选本机 `git` CLI（服务端克隆） |
| **下游** | 无（本模块是链路终点，不产出跨系统契约消息） |

### 1.1 明确不做 🔴

| 不做 | 原因 |
|------|------|
| 不访问**私有仓库**、不支持任意 GitHub 用户态操作 | 使用服务端统一凭证（平台级 Token 或匿名），**不接入用户 GitHub OAuth**；仅服务公开数据浏览场景 |
| 不做仓库写操作（star/fork/issue/PR/CI 触发） | 本模块是**只读情报工具**，非 GitHub 客户端替代品 |
| 不做定时全量采集入库（榜单不落库） | 榜单是**查询态**数据：TTL 缓存 + 失败快照回退，不落 PostgreSQL；避免把易变的第三方榜单当作自有数据资产管理 |
| 不实现 release / description 盯盘事件（V1） | proto 枚举已预留 `RELEASE`/`DESCRIPTION`，**当前仅产生 `STARS` 事件**；发布订阅属二期 |
| 不实现每日摘要 `daily_digest`（V1） | proto `RadarNotification.kind` 已预留，未实现 |
| 不绕过 GitHub 限流与 ToS | 匿名 60 次/小时或单 Token 5000 次/小时，靠缓存+退避+并发上限消化，**不多 Token 轮询** |
| 不把 AI 总结当作权威结论 | 三级总结是辅助速览，Prompt 明确要求「不编造、材料不足明说」，UI 标注模型与生成时间 |

## 3. 功能需求（FR-RAD-\*）

> 编号为本模块自造（RADAR 不在媒体矩阵 PRD 内，无既有编号可沿用），契约为准：proto 字段与本文描述不一致时以 proto 为准。
> 优先级：**P0 = 必须有** · **P1 = 应该有** · **P2 = 可以有**。

| ID | 名称 | 描述 | 验收标准 | 优先级 | 现状 |
|----|------|------|----------|--------|------|
| **FR-RAD-01** | 热门榜查询 | `GET /api/v1/radar/trending`：窗口 `since=today/week/month`，过滤 `language/topic/license/only_new/query`，排序 `hot/stars/updated/new`，分页 | 响应含 `items/total/window/refreshed_at/language_top/license_top/rising_count/new_count`；窗口过滤后 KPI 口径与分页一致 | **P0** | ✅ 已实现 |
| **FR-RAD-02** | 新星搜索 | `GET /api/v1/radar/rising`：周窗口内 `query/language` + 分页 | 走独立缓存键与快照；排序恒为热度 | **P0** | ✅ 已实现 |
| **FR-RAD-03** | stale 降级 | 抓取失败回退**最近一次成功快照**，响应 `stale=true + stale_reason`；所有响应头包含原因截断 ≤160 字 | 断网/限流场景返回 200 + stale 标记而非 500 | **P0** | ✅ 已实现 |
| **FR-RAD-04** | 仓库详情 | `GET /api/v1/radar/repo`：语言构成（字节数+占比）、Top8 贡献者、License SPDX、时间三元组（创建/更新/推送）；`include_readme` 时回带 README（截断 200KB）+ 2000 字摘录 | 语言/贡献者子请求失败**不阻塞**主响应 | **P0** | ✅ 已实现 |
| **FR-RAD-05** | AI 三级总结 | `POST /api/v1/radar/insight`：`brief`（≤50 字）/ `summary`（五节速览 200-400 字）/ `deep`（五节深度 500-900 字）；简体、Markdown、不编造 | 24h 缓存（`cached=true` 回显）；每仓库每级每日 3 次频控；未配置 LLM 时返回引导文案而非报错 | **P0** | ✅ 已实现 |
| **FR-RAD-06** | 源码浏览 | `GET /api/v1/radar/repo/tree`（递归，>1000 节点截断并标 `truncated`）；`GET /api/v1/radar/repo/content`（base64 解出 UTF-8 文本，NUL 判定二进制，>512KB 截断） | 空分支名回落默认分支；`path` 拒绝 `..` | **P1** | ✅ 已实现 |
| **FR-RAD-07** | 克隆 | `POST /api/v1/radar/repo/clone`：回 HTTPS/SSH/ZIP 三址 + 推荐命令；`to_server=true` 且管理员已开启时服务端 `git clone --depth 1`（60s 超时、已存在复用） | 服务端克隆**默认关**；未开启返回提示文案，`cloned=false` | **P1** | ✅ 已实现 |
| **FR-RAD-08** | 盯盘管理 | `GET/POST/DELETE /api/v1/radar/watches`：增删列，记录基线星标，行级按 `user_id` 隔离 | 重复添加幂等返回原记录；删除返回 404（不存在） | **P0** | ✅ 已实现 |
| **FR-RAD-09** | 盯盘事件 | 列表读时按需同步星标（节流 10min、单次 ≤12、并发 4）；相对上次记录新增 ≥**50** 星产生 `STARS` 事件；`GET /api/v1/radar/watch-events` + `POST .../read` | 未读数与事件表实时一致（mark read 后重算）；单用户事件上限 200 条、30 天物理清理 | **P0** | ✅ 已实现 |
| **FR-RAD-10** | 雷达通知 | `GET /api/v1/radar/notifications` + `POST .../read`：通知=当前用户盯盘事件视图（title=仓库，body=事件文案） | **不独立建通知表**；已读状态与盯盘事件联动；空 ids 拒绝（400） | **P0** | ✅ 已实现 |
| **FR-RAD-11** | 平台配置 | `GET/PUT /api/v1/radar/config`：GitHub Token / LLM(BaseURL/Key/Model) / 服务端克隆(开关+目录)；读=登录用户（脱敏回显 `abcd…wxyz`），写=系统/租户管理员；密钥 AES-256-GCM 加密落库；空串=保留原值 | 密钥**任何接口不回显明文**；非管理员写返回 403 | **P0** | ✅ 已实现 |
| **FR-RAD-12** | 演示模式 | `RADAR_DEMO=1` 环境变量切换内存演示榜单 | 仅本地联调/无外网环境用；生产默认关 | **P2** | ✅ 已实现 |

**P0 共 8 条全部已实现**。预留未实现：`RELEASE`/`DESCRIPTION` 事件、`daily_digest`、API Resource 权限资源挂载（见 04-开发进度 §4）。

## 5. 关键口径定义（避免歧义）

| 口径 | 定义 |
|------|------|
| **窗口增量 `stars_delta`** | trending HTML 解析出的官方口径「N stars today/this week/this month」。Search API 兜底引擎**无此字段**（为 0），此时「上涨数」KPI 与 `hot` 排序退化为总星近似 |
| **`is_new`** | 仓库 `created_at` 晚于当前窗口起点（日=24h/周=7d/月=30d，UTC） |
| **sparkline** | 最近 ≤7 个窗口增量点，跨快照差分累积；数据源重启后清零重建 |
| **基线 `baseline_stars`** | 加入盯盘时刻的星标数；盯盘增量 = 当前 − 基线 |
| **事件触发** | 相对**上一次已记录事件**的增量 ≥50 星；≤0 即关闭（当前恒 50） |
| **快照** | 进程内存态（非 Redis/DB）：进程重启后首轮抓取失败**无快照可回退**，直接 `stale_reason` 报错文案 |

## 6. 验收标准（子系统级）

RADAR 被认为「可用」需同时满足：

| # | 验收项 | 判据 |
|---|-------|------|
| 1 | 榜单可查 | 三窗口 × 全过滤维度组合请求均 200；`total` 与翻页一致；`stale=false` 时 `refreshed_at` 为当次 |
| 2 | 降级可信 | 断网重试后返回 `stale=true` 与上份快照（或明确原因），**不出现 500** |
| 3 | 详情完整 | 任一榜内仓库详情含语言构成/贡献者/License；README 可拉取（无 README 仓不报错） |
| 4 | AI 受控 | 未配 LLM 时返回引导文案；配置后三级均可生成；第 4 次/日/级被频控拦截并明示 |
| 5 | 盯盘闭环 | 加盯 →（人造阈值增量）→ 事件 + 未读 → 全部已读 → 未读归零；A 用户看不到 B 用户盯盘 |
| 6 | 密钥安全 | 库中无明文；`GET /config` 仅脱敏串；普通用户 `PUT /config` 得 403 |
| 7 | 治理生效 | 事件表 ≤200/人；30 天前事件被 cron 删除（日志有 `deleted=N`） |

## 8. 诚实声明

1. **trending HTML 解析会失效**：`github.com/trending` 无官方 API，HTML 结构改版即解析失败。已做双引擎兜底（Search API），但兜底口径只有「窗口内新建且总星排序」，**无官方窗口增量**——这是一个可被接受的降级，不是等价替代。
2. **快照在内存**：进程重启后缓存与快照清零，首轮失败无可回退数据；未引入 Redis 持久化（当前规模不必要，见概要设计 ADR-RAD-06）。
3. **匿名限额很紧**：未配 Token 时 60 次/小时的 GitHub 匿名限额在多人并发补全下很快见底。生产部署**必须**在设置中配置平台 GitHub Token，否则视为降级运行。
4. **AI 总结不保证正确**：三级 Prompt 均基于元数据+README 摘录推断，`deep` 级的「架构推测」明确标注为推测；材料不足时输出「材料不足，无法判断」。
5. **服务端克隆是唯一写磁盘路径**：目录由管理员配置，`full_name` 经严格校验（`/`→`__`），无路径穿越；但该功能会把外网代码落盘，**默认关闭**，开启即管理员知情同意。
