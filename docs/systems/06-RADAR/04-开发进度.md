## 4. 现存缺口与待办（按优先级）

### 4.1 高（建议下个迭代补）

- [ ] **API Resource 权限资源挂载**：radar 五组 11 个端点未进权限资源 seed；当前实际门禁 = JWT 登录 + 配置写管理员校验。若需按角色隐藏/禁用 radar 功能，须先补 seed + `super` 授权 + 前端菜单可见性联动
- [ ] **生产 Token 配置核验**：生产实例若未在设置页配置 GitHub Token，匿名 60 次/小时将在多人使用下快速耗尽（表现为大面积 stale）。上线 checklist 必查项

### 4.2 中（功能债，proto 已预留）

- [ ] `RELEASE` / `DESCRIPTION` 盯盘事件：需新增 release 轮询与描述 diff 逻辑（建议复用 on-read 节流通道，勿上 cron）
- [ ] `daily_digest` 每日摘要通知：`RadarNotification.kind` 已预留；建议接入平台站内信体系（与「通知=事件视图」的边界需重新评审，见概要 ADR-RAD-04）
- [ ] 测试补缺：`finalize` 过滤排序分页表驱动测试、`InsightService` 频控与缓存路径、config「空串保留」语义

### 4.3 低（工程卫生）

- [x] 前端 `types.ts` 双读适配收敛（**v1.1 已完成**）：统一 `normalize*` 单点归一化，组件只读本地 snake_case DTO；待 buf 生成物口径冻结后再评「以生成类型为唯一事实源」的类型级收敛

## 5. 演进与砍单顺序

后续投入若需收敛，**自上而下**砍：

```
1. 服务端克隆（关闭开关即下线，零代码）
2. AI deep 档（保留 brief/summary，省 2/3 token 上限）
3. 源码浏览（tree/content 下线，保留详情+README）
4. rising 新星搜索（保留 trending 主榜）
────────── 以下不建议砍 ──────────
   trending 榜单 + stale 降级（存在意义）
   盯盘 + 事件 + 通知（差异化价值）
   配置加密与管理员门禁（安全底线）
```

## 6. 风险登记（运行期）

| 风险 | 概率 | 影响 | 缓解状态 |
|------|------|------|---------|
| trending 页结构改版 | 中（GitHub 年均数次改版） | 增量口径失效 | ✅ 双引擎兜底 + 零命中显式报错，可巡检发现 |
| 匿名限额耗尽 | 高（未配 Token 时） | 大面积 stale | ⚠️ 依赖上线 checklist（§4.1）；已有多层缓存/stale 兜底 |
| LLM 成本/不可用 | 中 | AI 面板错误文案 | ✅ 默认关 + 频控 + 缓存 + 错误非 500 |
| 快照内存随重启丢失 | 低（单次重启冷启 10min） | 短时 stale | ✅ 可接受；多实例化时再评审 Redis 化 |
