## 1. 系统上下文

```
                    ┌──────────────────────────────────────┐
  平台热榜 ─────────►│                                      │
  官方 API ─────────►│        ① IC 情报收集系统              │
  RSS/Atom ─────────►│                                      │
  网页正文 ─────────►│                                      │
  直播流(授权) ─────►│                                      │
                    └───────────────┬──────────────────────┘
                                    │ mm.intel.normalized.v1
                                    │ （IntelItem 流）
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
              ② TT 全量       ③ MIA C_market   ④ MME B_material
                                                     │
                    ┌────────────────────────────────┘
                    │ mm.intel.blocked.v1
                    ▼
              人工合规队列（D 类 + 闸门命中）
```

**边界原则**：IC **只负责采与归一**，不判断「值不值得做」（那是 TT 的活），不判断「影响哪个标的」（那是 MIA 的活）。

## 2. 五层架构

```
┌─ L1 信源层  SourceRegistry ─────────────────────────────────────┐
│  五类信源：hotlist / keyword / creator / rss / competitor        │
│  可配：启停、频率、速率、优先级、凭据引用                          │
└──────────────────────────┬─────────────────────────────────────┘
                           │ 调度（asynq cron / 周期）
┌─ L2 采集层  Collector ───▼──────────────────────────────────────┐
│  五路可插拔适配器：hotlist / api / rss / crawl / sidecar         │
│  统一接口 Collector{ Fetch(ctx, Source) ([]RawFragment, error) } │
│  内建：限流、退避、超时、健康度上报                               │
└──────────────────────────┬─────────────────────────────────────┘
                           ▼ mm.intel.raw
┌─ L3 归一化层 Normalizer ────────────────────────────────────────┐
│  RawFragment → IntelItem（契约校验）                             │
│  三级去重：① URL 归一 ② SimHash 指纹 ③ embedding 语义            │
│  产出 cluster_id，保留多来源指针                                 │
└──────────────────────────┬─────────────────────────────────────┘
                           ▼
┌─ L4 理解层  Extractor ──────────────────────────────────────────┐
│  实体抽取（中英）· 情感 · 摘要 · 情报分类(ABCD) · 可加工性判定     │
│  可降级：LLM 不可用时退化为规则                                  │
└──────────────────────────┬─────────────────────────────────────┘
                           ▼
┌─ L5 治理层  Governance ─────────────────────────────────────────┐
│  合规闸门（敏感类目/黑名单/授权/robots）· 配额与速率               │
│  取证快照留存 · 审计日志                                          │
└──────────────────────────┬─────────────────────────────────────┘
                           ▼ mm.intel.normalized.v1 / mm.intel.blocked.v1
```

## 3. 模块划分（Go 包结构）

遵循 Kratos 分层（`server → service → biz → data`），IC 作为独立业务域挂载：

```
apps/server/
  api/media/v1/ic/
    source.proto           # 信源注册表 CRUD
    collector.proto        # 采集器管理、手动触发、健康度
    intel.proto            # IntelItem 查询、检索、证据导出
  app/admin/internal/
    biz/ic/                # 领域层（usecase + 端口）
      source_usecase.go
      collect_usecase.go
      normalize_usecase.go
      dedup.go             # 三级去重算法
      extract_usecase.go
      governance.go        # 合规闸门
      ports.go             # Collector / EvidenceStore / Embedder 端口
    data/ic/               # 仓储实现
      source_repo.go
      intel_repo.go
      cluster_repo.go
      evidence_store.go    # 对象存储 / 本地
    collector/             # ★ 采集器实现（biz 端口的实现，非 data 层）
      collector.go         # 统一接口 + 注册表
      hotlist.go           # newsnow 自部署适配器
      api.go               # 官方 API 适配器（YouTube/B站/Reddit…）
      rss.go               # RSS/Atom（可接 RSSHub）
      crawl.go             # Crawl4AI 正文抽取
      sidecar.go           # 录播侧车（P2）
      ratelimit.go         # 令牌桶 + 退避
      robots.go            # robots.txt 解析与缓存
    service/ic/            # proto 实现
    worker/ic/             # asynq 周期任务
      schedule.go
```

### 3.1 职责表

| 模块 | 职责 | 不做 |
|------|------|------|
| `biz/ic/collect_usecase.go` | 编排一次采集：取信源 → 调采集器 → 送归一化 | 不直接发 HTTP |
| `collector/*` | 与外界的**唯一**接触面 | 不做业务判断 |
| `biz/ic/dedup.go` | 三级去重与聚类 | 不做语义理解 |
| `biz/ic/governance.go` | 合规闸门判定 | 不做内容审核结论（只分流） |
| `data/ic/evidence_store.go` | 证据快照读写 | 不做清理策略（交 `pkg/retention`） |
| `worker/ic/schedule.go` | 周期触发 | 不含业务逻辑 |

## 4. 关键数据流

### 4.1 周期采集（主链路）

```
asynq cron 触发
  → collect_usecase.Run(sourceID)
     → 读 SourceRegistry 配置 + 解密凭据
     → robots 检查（crawl 路必需）
     → 令牌桶取令牌（不足则跳过本轮并计数）
     → collector.Fetch() → []RawFragment
     → 写证据快照 → evidence_ref
     → 发 mm.intel.raw
     → 归一化：RawFragment → IntelItem（schema 校验）
     → 三级去重 → cluster_id
     → 理解层：实体/分类/可加工性
     → 治理层：合规闸门
        ├─ pass   → 发 mm.intel.normalized.v1
        ├─ review → 落库 + 进人工队列
        └─ block  → 发 mm.intel.blocked.v1 + 告警
     → 更新信源健康度指标
```

### 4.2 手动补采（单 URL）

```
POST /api/v1/media/ic/collector/fetch
  { url, method: "crawl"|"api" }
  → 同主链路，但跳过 SourceRegistry 调度，直接单次执行
  → 用于运营临时补一条 / 正文抽取失败后手贴续跑
```

### 4.3 正文抽取失败降级（FR-INT-04）

```
Crawl4AI 失败
  ├─ 反爬      → 错误码 ANTI_BOT，提示「目标站点反爬，请手动粘贴正文」
  ├─ 超时      → 重试 1 次（退避 5s），仍失败 → 错误码 TIMEOUT
  └─ 空正文    → 错误码 EMPTY_CONTENT，提示「疑似 JS 渲染页，建议改用 API 路」
  → 三种错误均保留 evidence_ref，支持后续手贴续跑（同一 intel_id 补 payload.text）
```

### 4.4 回流（P2，FR-INT-16）

```
⑤ MAP 发 mm.map.feedback.v1
  → IC 订阅 → 更新 source 的选题权重字段
  → 权重影响 SourceRegistry 的调度优先级（不直接改开关）
```

## 5. 外部依赖与部署形态

| 依赖 | 形态 | 部署位置 | 失败影响 | 回退 |
|------|------|---------|---------|------|
| **newsnow** | **独立服务**（Node） | 自部署容器，内网 HTTP | 国内热榜全失效 | **直采回退**：各平台官方热榜页 / API |
| **RSSHub** | **独立服务**（Node） | 自部署容器，内网 HTTP | 长尾订阅失效 | 自研 RSS 解析器（`gofeed`）直连 |
| **Crawl4AI** | 独立服务 / Python 侧车 | 容器，HTTP 或 CLI | 正文抽取失效 | `go-readability` 降级 + 手贴续跑 |
| PostgreSQL 5434 | 基础设施 | 本机 | 元数据不可写 | 无（强依赖） |
| Redis 6380 | 基础设施 | 本机 | 限流降级为单机内存 | 单实例可接受 |
| NATS JetStream | 基础设施 | 本机 `D:/nats-server` | 下游全部断流 | 本地磁盘队列暂存（≤1h） |

> **关键约束**：newsnow / RSSHub **必须自部署**，禁止打公共实例（作者已公开呼吁；且公共实例不可用不可控）。

## 6. 接口契约

### 6.1 NATS

| Subject | 载荷 | 说明 |
|---------|------|------|
| `mm.intel.raw` | `RawFragment`（内部结构） | 采集器 → 归一化，**不过契约层** |
| `mm.intel.normalized.v1` | `IntelItem` | 闸门 pass |
| `mm.intel.blocked.v1` | `IntelItem` | 闸门 block，进人工 |

### 6.2 REST（`api/media/v1/ic`）

| 方法 | 路径 | 用途 |
|------|------|------|
| `GET/POST/PATCH/DELETE` | `/api/v1/media/ic/sources` | 信源注册表 CRUD（FR-INT-01） |
| `POST` | `/api/v1/media/ic/sources/{id}/toggle` | 启停 |
| `POST` | `/api/v1/media/ic/collector/run` | 手动触发一次采集 |
| `POST` | `/api/v1/media/ic/collector/fetch` | 单 URL 补采（FR-INT-04） |
| `GET` | `/api/v1/media/ic/collector/health` | 各信源健康度与配额（NFR-IC-05） |
| `GET` | `/api/v1/media/ic/intels` | 情报检索（FR-INT-14，全文+实体+时间） |
| `GET` | `/api/v1/media/ic/intels/{id}` | 单条详情 |
| `GET` | `/api/v1/media/ic/intels/{id}/evidence` | 导出证据包（FR-INT-11） |
| `POST` | `/api/v1/media/ic/intels/{id}/supplement` | 手贴正文续跑 |
| `GET` | `/api/v1/media/ic/briefings` | 情报简报（P2，FR-INT-17） |

### 6.3 前端页面（Quasar）

| 路由 | 页面 | 内容 |
|------|------|------|
| `/media/ic/sources` | 信源管理 | 表格 CRUD、启停开关、健康度徽标、配额进度条 |
| `/media/ic/intels` | 情报流 | 时间线列表、类目筛选、实体筛选、去重簇展开 |
| `/media/ic/intels/{id}` | 情报详情 | 正文、实体标签、证据链、来源指针 |
| `/media/ic/review` | 合规复核队列 | `review`/`block` 条目人工处置 |

菜单需在 `seed_service.go` 的 `platformMenuSeedRecords` 追加（FOLDER + MENU 成对）。

## 7. 关键技术决策（ADR 摘要）

| # | 决策 | 备选 | 选择理由 |
|---|------|------|---------|
| **ADR-IC-01** | 采集器抽象为**五路统一接口**，而非每平台一个客户端 | 每平台独立实现 | 新增信源零代码改动（FR-INT-01 验收判据） |
| **ADR-IC-02** | 热榜**默认走自部署 newsnow**，直采仅作回退 | 全部直采 | 直采 N 个平台 = N 份解析维护成本，且易触发风控 |
| **ADR-IC-03** | 三级去重**串行短路**（URL → 指纹 → 语义） | 三级并行 | 语义去重成本最高，前两级已拦掉 ~90%，省算力 |
| **ADR-IC-04** | 取证快照**只存引用不存正文** | 全量入消息 | 消息体膨胀会拖垮 NATS；合规只需可调取的证据 |
| **ADR-IC-05** | 合规闸门**在归一化之后、发布之前**，且无旁路 | 采集前过滤 | 采集前无法判断（需归一化后的实体/类目） |
| **ADR-IC-06** | 调度用 **asynq** 而非自研 ticker | goroutine + ticker | 仓库已有 asynq；天然支持重试、死信、可观测 |
| **ADR-IC-07** | 理解层**可降级**（LLM → 规则） | 强依赖 LLM | 外部 LLM 不可用时不得阻断采集主链路 |
| **ADR-IC-08** | FreshRSS **不采用** | 原调研列为主力 | 实测 **AGPL-3.0** 撞红线（PRD §9.1 纠正项） |

## 8. 容量与性能估算（V1 单实例）

| 项 | 估算 |
|----|------|
| 信源数 | 15–30 个 |
| 采集周期 | 热榜 30 分钟（**勿高于 newsnow 默认缓存频率**）；RSS 10 分钟；关键词 60 分钟 |
| 日产条目 | 约 3,000–8,000 条（去重后 800–2,000 条） |
| 日增存储 | 元数据 ~10MB + 证据快照 ~200MB（90 天约 18GB） |
| 峰值并发 | ≤8（可配） |

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| newsnow/RSSHub 改版失效 | 采集大面积中断 | ① 自部署锁定版本；② 直采回退路径；③ 信源健康度告警 |
| 平台反爬升级 | crawl 路成功率下降 | robots + 限流 + **优先热榜/API/RSS**；crawl 仅补充 |
| 语义去重误合并 | 不同事件被并成一簇 | 阈值可配 + 人工拆分 + 拆分行为记入调参样本 |
| 证据快照撑爆磁盘 | 存储成本失控 | 90 天留存 + `pkg/retention` 自动清理 |
| 凭据泄露 | 账号被盗用 | 加密存储 + 日志脱敏（NFR-IC-06） |
| LLM 成本失控 | 费用超预算 | 理解层可降级 + 云端调用总量帽（硬熔断） |

## 10. 与其他子系统的接口约定

| 对 | 约定 |
|----|------|
| → **② TT** | 全量 `IntelItem`。TT 依赖 `metrics._as_of` 判断快照新鲜度；`dedup.cluster_id` 是 TT 话题聚类的**重要输入但非唯一**依据 |
| → **③ MIA** | 仅 `category=C_market`。MIA 依赖 `entities`（confidence ≥0.6）做实体链接 |
| → **④ MME** | 仅 `category=B_material` 且 `workability.score` ≥ 阈值。MME 依赖 `payload.media_refs` 取素材 |
| ← **⑤ MAP** | 消费 `mm.map.feedback.v1`，更新信源权重（P2） |

**纪律**：下游**不得**反向要求 IC 增加仅自己需要的字段。确有需要走契约演进流程（共享文档 §9）。
