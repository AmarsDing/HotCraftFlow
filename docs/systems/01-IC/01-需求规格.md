# ① IC 情报收集系统 · 需求规格

> **子系统**：IC · Intelligence Collection · 情报收集
> **版本**：v1.0 · **日期**：2026-10-17
> **上游**：PRD §3 · 契约 [`../00-shared/01-data-contract.md`](../00-shared/01-data-contract.md) §1
> **作者**：架构 · **状态**：待评审

---

## 1. 目标与边界

| 项 | 内容 |
|----|------|
| **目标** | 持续、合规地从国内外媒体平台采集**可用于二次加工与分析**的情报条目，产出带**来源凭证与证据链**的 `IntelItem` 流 |
| **输入** | 平台热榜 / 关键词 / 订阅源 / 指定创作者 / 竞品账号 / 突发信号 |
| **输出** | `IntelItem` 流（NATS）+ 证据快照 + 素材指针 |
| **采集主题** | 时政人物、商界精英、行业发展、科技突破、新兴技术、社会热点 |
| **上游依赖** | 无（本系统是数据链路起点） |
| **下游** | ② TT（全量）、③ MIA（`C_market`）、④ MME（`B_material`） |

### 1.1 明确不做 🔴

| 不做 | 原因 |
|------|------|
| 不绕过登录墙 / 不破解签名 / 不绕过验证码 | 平台 ToS + 法律风险 |
| 不采集个人信息 / 不建立自然人画像 | PIPL |
| 不做一键搬运（原样转发） | 著作权；必须经 ④ MME 二次加工 |
| 不做安全侦察类 OSINT | 不同问题域（Sherlock / SpiderFoot / theHarvester 等，见 PRD §5.1） |
| 不采集评论/互动内容（V1） | 待决策 Q8，PIPL 风险显著 |
| 不承诺信源永不失效 | newsnow/RSSHub 为第三方聚合，平台改版会导致源失效 |

## 2. 用户故事

| # | 作为… | 我希望… | 以便… |
|---|------|--------|-------|
| US-1 | 内容运营 | 在一个界面配置要采集哪些平台热榜、哪些关键词、哪些创作者 | 不再靠人工刷榜找选题 |
| US-2 | 内容运营 | 看到同一个事件在多个平台的归并结果 | 判断这是不是真热点而非单平台噪音 |
| US-3 | 分析师 | 拿到带证据链的情报条目 | 合规审计时能自证来源 |
| US-4 | 合规人员 | 敏感类目与权利人黑名单的条目自动进人工队列 | 违规内容不流入加工 |
| US-5 | 运维 | 看到每个信源的健康度与配额消耗 | 源挂掉时能第一时间知道 |
| US-6 | 分析师 | 按类目/关键词生成周期性情报简报 | 快速掌握一段时间内的情报全貌 |

## 3. 功能需求（FR-INT-\*）

优先级：**P0 = 必须有** · **P1 = 应该有** · **P2 = 可以有**（可砍，见开发进度 §6）

| ID | 名称 | 描述 | 验收标准 | 优先级 |
|----|------|------|----------|--------|
| **FR-INT-01** | 信源注册表 | 热榜/关键词/创作者/RSS/竞品五类信源可配置 | 配置驱动；**新增一个信源不改代码**；启停与频率可配 | **P0** |
| **FR-INT-02** | 热榜采集器 | 接入多平台热榜（**默认自部署 newsnow**） | ≥10 国内 + ≥5 国外源；单源失败不影响其他 | **P0** |
| **FR-INT-03** | 采集器插件五路 | `hotlist` / `api` / `rss` / `crawl` / `sidecar` | 每路可独立启用；**契约一致**（同一 `Collector` 接口） | **P0** |
| **FR-INT-04** | 正文抽取 | URL → 干净 Markdown（复用既有 `FR-M16-01`，默认 **Crawl4AI**） | 反爬/超时/空正文三类错误**可读**，可手贴续跑 | **P0** |
| **FR-INT-05** | RSS 订阅采集 | 订阅 RSS/Atom（可接自建 RSSHub 服务） | 增量拉取不重复；断源可读告警 | **P0** |
| **FR-INT-06** | 归一化 IntelItem | 统一 schema（契约 §1） | 任意信源产出字段一致；schema 校验通过 | **P0** |
| **FR-INT-07** | 三级去重 | URL 归一 / 内容指纹（SimHash）/ 语义相似（embedding） | 同一事件跨源聚为一 cluster，保留多来源指针 | **P0** |
| **FR-INT-08** | 实体抽取 | 抽取人物/机构/地点/事件/话题；**需支持中英** | 中文可用（jieba/HanLP 级）；实体可检索 | **P1** |
| **FR-INT-09** | 情报分类 | 自动归入 A/B/C/D 四类 | 可人工纠正；纠正记入样本 | **P1** |
| **FR-INT-10** | 可加工性判定 | 判断能否产出视频（有素材/有观点/可解说） | 给出理由；低分不自动进 MME | **P1** |
| **FR-INT-11** | 取证快照 🔴 | 留存时间、URL、原始片段、抓取方式、响应头 | 可导出证据包（合规审计用） | **P0** |
| **FR-INT-12** | 合规闸门 🔴 | 敏感类目 / 权利人黑名单 / 授权状态 / robots 检查 | 命中进人工队列，**不得**自动进入加工 | **P0** |
| **FR-INT-13** | 配额与速率治理 | 多账号轮询、令牌桶限流、配额可视化、自动退避 | 超限自动退避；不触发平台封禁 | **P1** |
| **FR-INT-14** | 情报检索 | 全文 + 实体 + 时间范围检索历史情报 | 可选 MCP ≤3 tool（search/get/export） | **P1** |
| **FR-INT-15** | 录播侧车采集 | 直播开播监测 → 分段录像（±弹幕） | 学 DLR / rust-srec；**录 ≠ 剪**；**须授权** | **P2** |
| **FR-INT-16** | 表现数据回流接入 | 接收 ⑤ MAP 回流数据 | 更新选题权重 | **P2** |
| **FR-INT-17** | 情报简报 | 按周期生成情报简报（MD/HTML） | 可按类目/关键词定制；含来源链接 | **P2** |

**P0 共 8 条**，构成 Phase 1 的「IC 可用」最小集。

## 4. 非功能需求（NFR）

| ID | 名称 | 要求 |
|----|------|------|
| **NFR-IC-01** | 采集可用性 | 单信源失败**不阻断**其他信源；整体采集成功率 ≥95%（7 日滚动） |
| **NFR-IC-02** | 时效性 | 热榜条目从发布到入库 ≤ 采集周期 + 5 分钟 |
| **NFR-IC-03** | 幂等 | 同一 URL 在同一采集周期内重复采集**不产生**重复 `IntelItem` |
| **NFR-IC-04** | 合规 | 100% 条目经合规闸门；**无旁路** |
| **NFR-IC-05** | 可观测 | 每信源暴露健康度、延迟、成功率、配额消耗四项指标 |
| **NFR-IC-06** | 凭据安全 | 平台 token / Cookie 加密存储，**不进日志**（沿用 FR-M10-03） |
| **NFR-IC-07** | 资源占用 | 单进程内存 ≤1.5GB；采集并发可配，默认 ≤8 |
| **NFR-IC-08** | 留存 | 原始证据快照 ≥90 天；`IntelItem` 元数据 ≥1 年 |
| **NFR-IC-09** | 许可证 | 遵守 [`../00-shared/02-tech-selection.md`](../00-shared/02-tech-selection.md) 全部红线；Crawl4AI 保留 Attribution |

## 5. 信源矩阵需求

### 5.1 国内

| 平台/源 | 采集路 | 可得内容 | 姿态 | 备注 |
|---------|-------|---------|------|------|
| 微博 / 百度 / 知乎 / 头条 | **热榜** | 热搜词、排名、链接 | **Depend newsnow**（自部署） | 主力 |
| 抖音 | 热点榜 + 录播侧车 | 热点词、视频元信息 | 热榜 + 侧车 | 侧车须授权 |
| B站 | 公开 API + **RSSHub** + 热榜 | 视频元信息、UP 主动态、字幕 | Depend | 较友好 |
| 快手 / 小红书 | 热榜 + 关键词页 | 标题/热度/互动 | 抓取（严守 robots） | 小红书风控严 |
| 公众号 / 财新 / 华尔街见闻 | **RSSHub** 路由 或 Crawl4AI | 长文正文 → MD | RSSHub 独立服务 | AGPL 边界见选型文档 |
| 交易所 / 监管公开 feed | RSS / 官方 API | 公告、政策原文 | Depend | MIA 重要输入 |
| **视频号** | **受限** | — | **诚实标注不可用** | 无开放采集能力 |

### 5.2 国外

| 平台/源 | 采集路 | 可得内容 | 姿态 | 备注 |
|---------|-------|---------|------|------|
| YouTube | **Data API v3** + yt-dlp | 元信息、字幕、Trending | 官方 API 优先 | |
| TikTok | Research/Display API 或热榜 | 元信息 | 优先官方 API | 需资质 |
| Reddit / HN / Product Hunt | **官方 API / RSS** | 帖子、科技热点 | Depend | 友好 |
| X / Threads / LinkedIn | 官方 API | 文本 | 可选 | **有配额成本** |
| Reuters / Bloomberg / FT / 央行 / SEC | RSS + Crawl4AI | 财经时政正文 | 抓取（守 robots） | MIA 重要输入 |
| Instagram / Facebook | Graph API | 有限 | 困难 | 需商务审核，**诚实标注** |

> **红线**：优先**热榜聚合 / 官方 API / RSS**；网页抓取仅作补充，须守 `robots.txt`、频率限流、不采集个人信息、不破解鉴权。

## 6. 情报分类（四类，决定下游路由）

| 类 | 说明 | 下游 |
|----|------|------|
| **A. 热点情报** | 正在上升的话题/事件 | → ② TT |
| **B. 素材情报** | 可直接获取的可加工素材（长视频/文章/播客） | → ④ MME 直接建任务 |
| **C. 市场情报** | 时政/政策/公司/科技突破等可能影响市场的消息 | → ③ MIA |
| **D. 合规情报** | 平台规则变更、版权警示、政策信号 | → **阻断** + 告警，进人工 |

## 7. 验收标准（子系统级）

IC 被认为「可用」需同时满足：

| # | 验收项 | 判据 |
|---|-------|------|
| 1 | 信源可配置 | 新增一个热榜信源，从配置到出数据 **≤10 分钟、零代码改动** |
| 2 | 覆盖度 | 稳定产出 ≥10 国内 + ≥5 国外信源，连续 7 日成功率 ≥95% |
| 3 | 去重有效 | 人工抽样 100 条跨源同事件条目，归并正确率 ≥85% |
| 4 | 取证完整 | 随机抽 20 条，证据包**全部**可导出且含时间/URL/抓取方式/响应头 |
| 5 | 合规无旁路 | 代码审计确认**不存在**绕过 FR-INT-12 的发布路径 |
| 6 | 故障隔离 | 人为下线 3 个信源，其余信源采集不受影响 |
| 7 | 契约合规 | 产出消息 100% 通过 `IntelItem` JSON Schema 校验 |

## 9. 诚实声明

1. **信源会失效**：newsnow / RSSHub 是第三方聚合，平台改版会导致源失效。必须有**直采回退**能力，不做「没有聚合器就瘫痪」的设计。
2. **覆盖度是目标态**：§5 表格中标注「困难」「受限」的平台（视频号、Instagram、Facebook），V1 **很可能无法实现**，此处诚实标注而非承诺。
3. **实体抽取中文效果未经实测**：jieba/HanLP 的效果需实机验证后调参，本需求不承诺准确率数字。
4. **去重正确率 85% 是工程目标非承诺**：语义去重的边界天然模糊，验收以人工抽样为准。
