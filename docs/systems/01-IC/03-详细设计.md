## 3. 采集器接口与实现

### 3.1 统一接口

```go
// biz/ic/ports.go
type Collector interface {
    // Method 返回本采集器对应的采集路
    Method() contract.CollectMethod

    // Fetch 执行一次采集。返回的 RawFragment 不做业务判断。
    Fetch(ctx context.Context, src *Source, opts FetchOptions) ([]RawFragment, error)

    // Health 上报本采集器的可用性（不发真实请求）
    Health(ctx context.Context) error
}

type RawFragment struct {
    SourceID    string
    Platform    string
    Region      string
    Method      contract.CollectMethod
    URL         string
    Author      string
    Title       string
    Text        string
    MediaRefs   []string
    Metrics     contract.Metrics
    CollectedAt time.Time
    Raw         []byte          // 原始片段（写证据）
    HTTPHeaders map[string]string
    FinalURL    string
    HTTPStatus  int
}

type FetchOptions struct {
    Timeout   time.Duration
    RateLimit RateLimit        // 令牌桶参数
    Since     *time.Time       // 增量拉取起点（RSS 用）
    Retry     int
}
```

### 3.2 采集器注册表

```go
// collector/collector.go
var registry = map[contract.CollectMethod]Collector{}

func Register(c Collector) { registry[c.Method()] = c }
func Get(m contract.CollectMethod) (Collector, bool) { c, ok := registry[m]; return c, ok }
```

各采集器在 `init()` 中自注册，新增一路**零改动**核心代码。

### 3.3 五路实现要点

| 路 | 实现 | 要点 |
|----|------|------|
| **hotlist** | HTTP 调自部署 newsnow `/api/s?id=<platform>` | ① 保持 30 分钟周期（newsnow 默认缓存 30 分钟，**更频繁无意义**）；② 失败时逐平台直采回退；③ 记录 `rank`/`rank_total` 供 TT 用 |
| **api** | 平台官方 API（YouTube Data API v3、B站、Reddit…） | ① 凭据从 `credential_ref` 解密取；② 配额计数写入 Redis；③ 429 自动退避 |
| **rss** | `gofeed` 解析；可指向自部署 RSSHub 路由 | ① 用 `If-None-Match`/`If-Modified-Since` 增量；② 用 `guid` 或 `link` 做幂等键；③ 断源（连续 N 次 404/超时）**可读告警** |
| **crawl** | HTTP 调 Crawl4AI 服务 → Markdown | ① **先查 robots**；② 三类错误可读（见 §5）；③ 保留 Attribution（NFR-14） |
| **sidecar** | 外部录播进程（DLR / rust-srec）产出文件后由 IC 收编 | ① **须授权录制**；② 录 ≠ 剪；③ 默认进人工审核 |

### 3.4 速率治理

```go
// collector/ratelimit.go
type RateLimiter interface {
    Wait(ctx context.Context, key string) error   // 取令牌，ctx 取消则放弃
    Backoff(key string, failCount int) time.Duration
}
```

- 实现：Redis 令牌桶（多实例共享）+ 进程内 LRU 兜底
- Key 维度：`platform`（平台级）优先于 `source`（信源级），避免同一平台被多个信源打爆
- 退避：指数退避 `min(2^n × 5s, 15min)`，加 ±20% 抖动（避免多信源同时重试）

### 3.5 robots 检查

```go
// collector/robots.go
type RobotsChecker interface {
    Allowed(ctx context.Context, u string, ua string) (bool, error)
}
```

- 缓存：Redis，TTL 24h（robots.txt 变动不频繁）
- **失败开放策略的例外**：robots 抓取失败时**保守放行**但标记 `robots_checked=false`，并降低该条目的合规信任度 → **不自动进 MME**
- crawl 路**强制**检查；api/rss/hotlist 路按平台条款豁免（记录理由）

## 4. 三级去重算法

### 4.1 L1 URL 归一

```
1. 小写化 scheme 与 host
2. 去除默认端口（:80 / :443）
3. 去除尾斜杠
4. 去除常见追踪参数：utm_*、from、spm、ref、share_token、_ga、fbclid、gclid...
5. 参数按 key 字典序重排
6. 去除 fragment
7. sha256 → url_key
```

> **注意**：短链（t.cn / dwz.cn / bit.ly）**必须**先展开再归一，否则同一 URL 会产生多个键。展开失败时按原 URL 处理并标记。

### 4.2 L2 SimHash 指纹

```
1. 文本清洗：去 HTML、去标点、去停用词（中英双表）
2. 中文按 2-gram 切分；英文按空格分词
3. 词权重 = 词频 × IDF（IDF 表离线统计，周更）
4. 每个词 hash 成 64 位 → 按位加权累加 → 降维得 64 位 SimHash
5. 汉明距离 ≤3 判定为近似重复
```

- 存储：`fingerprint uint64` 字段
- 检索：为加速，将 64 位切 4 段各 16 位建**倒排索引**（ pigeonhole 原则），避免全表扫描

### 4.3 L3 语义相似（embedding）

```
1. 取 title + text 前 512 token
2. 调 embedding 模型（本地优先；云可配）
3. 与近 24h 内同 region 的条目向量做余弦相似度
4. 相似度 ≥0.86 → 并入同一 cluster
```

- **成本控制**：L3 只对 L1/L2 未命中且 `category != D_compliance` 的条目执行；预计占总量的 10% 以内
- 向量**不存** PostgreSQL，存独立向量库或 Redis Stack（V1 可用 Redis VSS 简化）

### 4.4 聚类合并

```
新条目 X:
  c1 = 按 url_key 查 cluster      命中 → 合并，merged_by=url
  c2 = 按 fingerprint 汉明≤3 查   命中 → 合并，merged_by=fingerprint
  c3 = 按 embedding 余弦≥0.86 查  命中 → 合并，merged_by=embedding
  若 c1/c2/c3 命中不同 cluster → 取成员最多的为主，其余并入，记 merge 事件
  若均未命中 → 新建 cluster（cl_ + ULID）
```

**人工干预**：提供 `SplitCluster` / `MergeCluster` API，操作记入调参样本表（用于后续阈值优化）。

## 5. 合规闸门

```go
// biz/ic/governance.go
type Gate interface {
    Evaluate(ctx context.Context, item *contract.IntelItem) GateResult
}

type GateResult struct {
    Decision  Gate   // pass / review / block
    Reasons   []GateReason
    RuleIDs   []string
}
```

### 5.1 四类规则

| 规则类型 | 判据 | 默认动作 |
|---------|------|---------|
| `sensitive_category` | 类目/关键词命中敏感清单 | `block` |
| `rights_holder_blacklist` | 权利人黑名单（作者/机构） | `block` |
| `authorization` | 素材授权状态未知/未授权 | `review` |
| `robots` | `robots_allowed=false` | `block` |

- 多重命中取**最严**（`block` > `review` > `pass`）
- 命中记录 `RuleIDs`，**可解释**（合规审计要求）
- **无旁路**：代码审计需确认所有产出路径都经过 `Gate.Evaluate`

### 5.2 分流

```
pass   → mm.intel.normalized.v1
review → 落库 + 人工队列（前端 /media/ic/review）
block  → mm.intel.blocked.v1 + 告警 + **不进加工/分析**
```

## 8. 错误处理与错误码

| 错误码 | 场景 | 处置 |
|--------|------|------|
| `IC_SRC_NOT_FOUND` | 信源不存在 | 前端提示 |
| `IC_SRC_DISABLED` | 信源已停用 | 跳过 |
| `IC_ROBOTS_DISALLOWED` | robots 禁止 | 拒绝采集 + 告警 |
| `IC_RATE_LIMITED` | 令牌不足 | 跳过本轮，计 `skipped` 指标 |
| `IC_UPSTREAM_TIMEOUT` | 上游超时 | 退避重试（最多 2 次） |
| `IC_ANTI_BOT` | 反爬 | **不重试**，返回可读提示 + 建议手贴 |
| `IC_EMPTY_CONTENT` | 空正文 | 提示「疑似 JS 渲染，建议改用 API 路」 |
| `IC_SCHEMA_INVALID` | 归一化后 schema 校验失败 | 落 `dead_letter` 表 + 告警（不丢数据） |
| `IC_CREDENTIAL_INVALID` | 凭据失效 | 停用信源 + 告警（不清凭据便于排查） |

**死信处理**：`dead_letter` 表保留失败消息，提供重放入口。
