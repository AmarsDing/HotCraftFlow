## 2. 「矩阵」三维度

> 这是本子系统区别于「单条剪辑工具」的核心。

| 维度 | 含义 | 规格 |
|------|------|------|
| **A 平台矩阵** | 同一内容 → 多平台规格 | **9:16**（抖音 / TikTok / Shorts / Reels）· **1:1**（小红书 / IG）· **16:9**（B站 / YouTube） |
| **B 内容矩阵** | 同一素材源 → 多条不同选题 | 长片 → N 个高光片段；报告 → 解说片 / Overview / 图文 |
| **C 变体矩阵** | 同一条 → 多版本 A/B | 不同 **Hook**（前 3s）· 不同封面 · 不同标题 · 不同字幕皮肤 |

**矩阵规模示例**：1 个 30 分钟访谈 → 5 个高光（B）× 3 种画幅（A）× 2 个 Hook（C）= **30 个成片变体**。

> **这正是为什么需要 `VariantSet`**：没有统一容器，30 个文件会变成无法管理的散沙。

## 3. 加工流水线

```
素材获取（M2：yt-dlp / 本地 / ② TT 选题送入）
  ↓
转写 ASR（M3：源字幕 > 本地 Whisper/FunASR > 云）
  ↓
理解（M4：章节/要点/高光候选；M13：双报告 + 关键帧 + 极速模式）
  ↓
脚本（M5：平台文案；M14-06：报告→解说片；M14-08：Overview）
  ↓
★ 矩阵展开（FR-MIX-*：一源 N 版 × 多画幅 × 多变体）
  ↓
渲染（M6：9:16 reframing、≥2 档字幕、封面、manifest 自检）
  ↓
交接（M15：剪映草稿；M9-08：FCPXML；M9-01：ZIP 发布包）
  ↓
VariantSet → ⑤ MAP
```

> **★ 标记处是本增量的插入点**——在既有「脚本 → 渲染」之间插入矩阵展开层。

## 4. 增量功能需求（FR-MIX-\*）

| ID | 名称 | 描述 | 验收标准 | 优先级 |
|----|------|------|----------|--------|
| **FR-MIX-01** | 变体簇 `VariantSet` | 一源多版统一管理单元（契约 §4） | 含 N×(视频+文案+封面+manifest)；可整体送审 | **P1** |
| **FR-MIX-02** | 一次分析多次成片 | 转写/分析产物缓存复用 | 二次成片**不重跑** ASR/LLM | **P1** |
| **FR-MIX-03** | 多画幅批量渲染 | 同切点批量出 9:16 / 1:1 / 16:9 | 一次确认出三种；各自 manifest | **P1** |
| **FR-MIX-04** | 平台文案差异化 | 按平台生成标题/简介/话题 | ≥4 套语气（抖音/小红书/B站/Shorts） | **P1** |
| **FR-MIX-05** | 差异化度检查 | 同簇内两两相似度检测，过近似告警 | 给相似度分；过低提示改 Hook/封面 | **P2** |
| **FR-MIX-06** | 批量审核台 | 变体网格视图，批量勾选/驳回/重渲 | 一次审 ≥10 条；**驳回须填原因** | **P1** |
| **FR-MIX-07** | 素材去重库 | 跨任务指纹去重与引用计数 | 同源素材不重复落盘 | **P2** |
| **FR-MIX-08** | 混剪模板 | 开场/转场/结尾模板，保证矩阵一致性 | ≥3 套；模板变更可批量重渲 | **P2** |

**P1 共 5 条**，构成「MME 矩阵化」最小集。

## 5. 非功能需求（NFR）

| ID | 名称 | 要求 |
|----|------|------|
| **NFR-MME-01** | 渲染性能 | 单条 60s 9:16 成片渲染 ≤3× 实时（无 GPU 环境可放宽并在 UI 标注） |
| **NFR-MME-02** | 缓存有效 | 二次成片**不重跑** ASR/LLM；命中率 ≥95% |
| **NFR-MME-03** | 质检强制 | 渲染后自检（边界/字幕/时长/manifest）；不合格**不得**进审批门 |
| **NFR-MME-04** | 存储去重 | 同源素材引用计数，不重复落盘 |
| **NFR-MME-05** | 成本 | 云 LLM 调用总量帽；Ollama 降级通路可用 |
| **NFR-MME-06** | 合规 🔴 | 二创须**实质性转化**；差异化度检查纳入质检 |
| **NFR-MME-07** | 许可 | 遵守 NFR-09/12/13/14：无 AGPL 进仓；Crawl4AI 保留 attribution |
| **NFR-MME-08** | 可恢复 | 渲染任务可断点重试；失败保留中间产物便于排查 |

| # | 作为… | 我希望… | 以便… |

| US-1 | 内容运营 | 一次确认就出 9:16 / 1:1 / 16:9 三种画幅 | 不用逐个手动渲 |

## 7. 验收标准（矩阵化增量）

| # | 验收项 | 判据 |
|---|-------|------|
| 1 | 变体簇可用 | 单源产出 ≥12 个变体的 `VariantSet`，结构完整可整体送审 |
| 2 | 多画幅 | 一次确认出 3 种画幅，各自 manifest 独立且字段完整 |
| 3 | 缓存复用 | 二次成片 ASR/LLM 调用次数为 0 |
| 4 | 文案差异 | 4 套平台文案人工判定「语气有差异」比例 ≥80% |
| 5 | 批量审核 | 网格视图一次勾选 ≥10 条送审；驳回强制填原因 |
| 6 | 差异化检查 | 构造 3 组近似变体，系统全部告警并给出相似度分 |
| 7 | 质检门禁 | 人为构造不合格成片，`qc=false` 且**无法**进入审批门 |
| 8 | 契约合规 | `VariantSet` 100% 通过 JSON Schema |

> **基础能力验收（S1–S7）见** `doc-archive-20261017/av-automation-mvp-schedule-0.8.md` §9，本文不重复。

## 9. 诚实声明 🔴

1. **矩阵放大合规风险**：同一素材发 12 个平台意味着著作权风险 ×12。差异化度检查（FR-MIX-05）是**风控措施**不是可选项。
2. **Q1 未拍板前，素材来源默认限定为「自有 / 授权 / CC」**。热点仅作**选题灵感**而非素材源——这是本需求的默认立场。
3. **无 GPU 时 reframe 质量会下降**，必须诚实标注，不得宣称「AI 智能重构画面」。
4. **剪映草稿版本兼容性未验证**（标 `[待测]`），不承诺支持全部剪映版本。
5. **Overview 是自研最小实现**，不对标 NotebookLM 等商业产品。
6. **渲染是算力密集**：30 个变体的渲染时间会显著长于单条，需在 UI 提供进度与预估时间，不得让用户误以为卡死。
