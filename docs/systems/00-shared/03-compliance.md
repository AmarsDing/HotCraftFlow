# 00 · 合规、风控与法务边界

> **版本**：v1.0 · **日期**：2026-10-17
> **上游**：PRD §10（合规、许可与风控）
> **性质**：本文是**工程侧风险清单**，**不构成法律意见**。正式商用前**必须**由法务出具书面意见。
> **强制等级**：标 🔴 的条目为**不可后置、不可砍单**，任一违反即视为系统不可上线。

---

## 1. 内容合规（最高优先级）

### 1.1 著作权 🔴

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| 二次剪辑涉改编权 / 信息网络传播权 | **矩阵分发会把单条侵权放大成十几条** | ① 优先**自有 / 已授权 / CC 协议**素材；② 二创必须**实质性转化**；③ 标注来源作者；④ 商用前法务审查 |

**🔴 硬性规则**：
- **禁止原样切片搬运**（整段/整条直接转发）
- **禁止**把他人视频仅加边框、变速、镜像后发布——这不属于实质性转化
- 实质性转化的工程判据（写入 MME 质检）：新增解说/评论/论证结构 + 素材占比 + 差异化度检查（FR-MIX-05）

> **待决策 Q1**：是否做「他人热点内容切片搬运」？**建议 V1 不做**，热点仅作**选题灵感**而非素材源。此项直接决定 MME 素材来源与法务风险量级。

### 1.2 新闻版权

新闻正文有版权，**适合内部分析，不宜整篇再分发**。

- MIA 结论**默认仅内部使用**（待决策 Q2）
- 对外发布必须走**二次创作**路径，且引用量遵循「少量引用 + 明确出处 + 链接原文」
- **禁止**把抓取的正文整篇作为图文发布到任何平台

### 1.3 投资建议风险 🔴

MIA 的市场影响结论可能被误读为荐股/喊单。

| 措施 | 落实位置 |
|------|---------|
| 每份 `ImpactCard` **强制带 `disclaimer` 字段**，为空则不允许落库 | 契约层校验（`00-shared/01-data-contract.md` §3） |
| 文案固定为「研究/监测辅助，非投资建议；模型输出须人工复核」 | MIA 详细设计 |
| 跨资产传导结论**必须标 `confidence`**，且 UI 明示「假设非因果」 | 契约 + 前端 |
| 高影响推送（FR-MIA-12）**必须**含影响路径与免责声明 | MIA 推送模板 |
| **待决策 Q2**：V1 **仅内部使用**，对外发布须法务审 | PRD §12 |

### 1.4 平台 ToS

自动化发布、多账号矩阵可能违反平台服务条款。

- 优先使用**官方开放平台**（需企业资质）
- 账号池**克制**：V1 单平台 ≤3 账号（待决策 Q7），观察封号率后再调整
- 频率限流 + **拟人化节奏**（非均匀间隔、有合理操作间隔）
- **诚实标注**：视频号等无开放发布 API 的平台，标「暂不支持」，**不承诺**

### 1.5 数据合规（PIPL）🔴

| 规则 | 说明 |
|------|------|
| 只采集**公开内容的元信息与聚合统计** | 标题、排名、互动数、发布时间 |
| **不采集 / 不存储用户个人信息** | 不采集个体用户 ID 画像、不建立自然人档案 |
| **不采集互动/评论内容**（待决策 Q8） | V1 只采集聚合统计量 |
| 取证快照**最小必要 + 留存期** | 默认 90 天，到期自动清理（可复用 `pkg/retention`） |

### 1.6 抓取合规

| 规则 | 说明 |
|------|------|
| 守 `robots.txt` | 采集前解析并缓存，禁止访问 Disallow 路径 |
| 速率限制 | 令牌桶 + 自动退避；newsnow 作者已公开呼吁「勿竭泽而渔」 |
| 优先热榜 / 官方 API / RSS | 网页抓取**只作补充**，不作为主力 |
| **必须自部署 newsnow**（待决策 Q4） | 禁止高频打公共实例 |

### 1.7 内容安全 🔴

自动加工可能产出违规内容。三道防线**缺一不可**：

```
① 敏感词与类目过滤（FR-INT-12 合规闸门）—— 采集侧拦截
② 人工审核闸门（FR-PUB-04 审批门）      —— 发布侧拦截
③ 默认私密后再升公（NFR-17）            —— 兜底
```

### 1.8 直播录制

未授权录制风险高 → **须授权录制**（FR-INT-15），默认进人工审核队列。

## 2. 工程风控

| 风险 | 缓解措施 | 落实子系统 |
|------|---------|-----------|
| 平台风控封号 | 账号池隔离、频率限流、**异常自动熔断**（连续失败 N 次暂停该账号） | ⑤ MAP |
| 凭据泄露 | 本地加密（FR-M10-03 / FR-PUB-05），**日志脱敏** | ⑤ MAP |
| 自动化失控 | 审批门 + 默认私密 + 操作审计 + **发布总量上限** | ⑤ MAP |
| 成本失控 | 费用估算（FR-M12-01）+ 云端调用总量帽（硬上限，超阈值熔断） | ④ MME / ③ MIA |
| 上游依赖失效 | newsnow / RSSHub 为第三方聚合，平台改版会失效 → **须自部署 + 直采回退** | ① IC |
| 数据膨胀 | 时序降采样、取证快照留存期、素材引用计数去重 | ② TT / ① IC / ④ MME |

### 2.1 熔断规则（MAP 强制）

| 触发条件 | 动作 |
|---------|------|
| 单账号连续 3 次发布失败 | 暂停该账号 30 分钟 + 告警 |
| 单平台 24h 内失败率 > 50% | 暂停该平台全部账号 + 人工介入 |
| 24h 发布总量超过阈值 | 硬阻断，需人工解除 |
| 凭据失效 / 鉴权失败 | 立即停用账号，**不清凭据**（便于排查），标记待重新授权 |

## 3. 不可后置清单 🔴

下列四项在 PRD §11.1 明确为**不可后置、不可砍单**，任何排期调整都不得移除：

| # | 项目 | 为什么不可后置 |
|---|------|--------------|
| 1 | **GPL/AGPL 禁令** | 事后发现许可证污染，返工成本 = 重写整个模块 |
| 2 | **审批门（FR-PUB-04）** | 无审批门的自动发布 = 违规内容直通公网 |
| 3 | **默认私密（NFR-17）** | Open-Dispatch 默认 `public`，沿用会直接炸 |
| 4 | **取证链（FR-INT-11）** | 合规审计时无法自证来源，属于事后无法补录的证据 |

## 6. 诚实边界

1. **本文不是法律意见**：是工程侧风险清单，正式商用前须法务出具意见。
2. **合规不是一次性**：平台 ToS、监管政策会变，需季度复核。
3. **矩阵放大效应**：同一内容发到 12 个平台，意味着**合规风险 ×12**。任何单点合规疏漏都会被矩阵放大——这是本系统与普通单平台工具的根本差异。
4. **「技术上能抓」≠「法律上可以抓」**：采集器的能力边界必须小于法律边界（FR-INT-12 合规闸门是这一原则的技术落地）。
