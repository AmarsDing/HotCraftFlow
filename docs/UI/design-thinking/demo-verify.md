## 3. 三处建议的文档精修（ADJUST）

### ① 辉光特许的数量表述（总论#8 / SPIDERORB 决策4）
- **发现**：本屏稳态辉光 = LED 计数器 + PUB hub 两处；事件态再加金门 = **三处**。SPIDERORB 原文说"唯二特许"，但总论#8 说"全屏发光元素一只手数得过来"。两个口径在第三处辉光出现时不矛盾但容易较真。
- **建议**：总论#8 的"一只手数得过来"为准；SPIDERORB 篇补一句"事件态辉光（审批/告警出现期间）不计入稳态配额"。

### ② lerp 系数 0.12 不适用于离散状态计数（GrokBot 决策5）
- **发现**：`PENDING YOU` 是离散待办数，用 0.12 慢爬坡时，顶栏读到 `1` 而金门已显示 `3 drafts`——**同一状态两处瞬时不同值**（约 1 秒收敛窗），这正是 SPIDERORB 决策10"unit 自洽/无一处假"所禁止的穿帮。
- **建议**：01-grokbot.md 决策5 补一条细则："lerp 用于比率/金额/吞吐等连续量；**离散状态计数（待办数、在线数）应快照直写**或把 lerp 系数提到 0.35+，保证两处语义强绑定的数字同帧一致"。

### ③ 85:15 是稳态配比，需注明事件峰值豁免（SPIDERORB 决策1）
- **发现**：金门武装 + 待审批行 + LED + 徽章同时亮起时，霓虹面积实测冲到 ~18–20%；事件消化后回落到 ~13%。
- **建议**：04-spiderorb.md 决策1 补一句："85:15 按稳态测量；告警/审批等事件态允许短暂上浮至 ~20%，事件关闭即回落——配比的约束对象是**常态**，不是峰值"。

## 4. 实现过程中验证的其他文档元论断

1. **"不要相信肉眼验收"（总论·五步法 #5）再次被验证**：本 demo 的 pipeline 画布因一行 JS 展开运算符顺序错误（`{x: a.x*pw, ...a}` —— `...a` 把算好的 x/y 覆盖回比例值）把全部节点画进了左上角 1px 内。该 bug 活过了两轮肉眼截图检查，最终靠**在画布内绘制硬编码参考十字**（坐标自证）才定位。教训与原句完全同构。
2. **测量环境必须匹配显示环境**：Chrome `--dump-dom` 默认视口 800×600，flex 布局塌缩到 `win=762`，一度产生"中栏只有 355px"的假线索；带上与截图一致的 `--window-size` 后实测 `col=607` 正常。**验证工具本身也是设计对象。**
3. **辅助装置不能遮蔽被检验对象**：DOC CHECK 面板初版默认展开，恰好遮住了决策队列与金门（检验项 #8/#9 的锚点）——改为默认折叠后才成立。写检验工具时，"检验面板自身的布局纪律"也要过同一套哲学。
