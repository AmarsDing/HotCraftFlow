# GrokBot 仪表盘 · 设计思想

> 这套设计的精神：把"AI 通宵替你赚钱"这件抽象的事，拍成一部你能躺床上看完的默剧——你什么都不用点，只要每隔一会儿掀开眼皮确认：绿灯、 profits 在涨、没人闯祸。

## 1. 它在解决什么问题

看使用场景（视频帧就是对场景的白描）：22:07，竖屏手机，一张深色卡片浮在朦胧的彩色光斑上。这不是工作台，这是**床头**。

用户的真实处境有三层，每一层都对应一组设计回答：

- **"我不在电脑前，但我想知道一切正常。"** → 于是有一个永远亮着的利润大数字（`+$710.32`，绿色、发光、34px），一屏里只有它用了这种待遇。用户掀开眼皮只需视网膜余光扫到那团绿光，就能翻身继续睡。
- **"出事的时候，得只烦我一次，而且让我一键了结。"** → 于是有非模态审批弹窗（`SIGN · translator · 4.3k tok/s · $3.90/1M`，`[approved] [deny]` 两个幽灵按钮）、有待审批行用点线琥珀框占位，系统替你排队，不替你决定。
- **"这些 AI 到底是谁？我得拟人化地记住它们。"** → 于是 SCOUT/QUANT/RISK/ROUTER/YOU 五个角色每人一个生物形状、一个专属色、一句工作状态（`scanning 14 clusters` / `asleep · on call`）。把"系统状态"翻译成"员工值班表"，信任就有了着落。

一句话：这是一个**信任界面**，不是操作界面。它的 KPI 不是点击率，是"用户敢去睡觉"。

## 2. 视线动线与信息架构

以 t3p88 帧实测，视线的落点被安排成一条明确的动线：

1. **第一眼：右上绿色发光大字 `+$710.32`**。全屏最高亮度 + 最大字号 + 唯一发光文字，三者叠加强制第一眼。它回答唯一重要的问题："赚了吗？"
2. **第二眼：左上 Grok Bot 头像 + `night shift · 03:26`**。回答"谁在看店、现在几点"。制造拟人信任。
3. **第三眼：角色行五个彩色生物**。青、紫、红、粉星、白——一眼确认"全员在岗"。
4. **然后才是工作区三栏**：CLIENTS（谁在用）→ ROUTER 网络（流量怎么走）→ GPU NODES（机器怎么样）。三栏比例 ≈ 1 : 1.95 : 1.5——**中栏网络图拿走近一半宽度**，因为它是"系统活着"的证据（点链在流动、数字在跳），其余两栏是凭证列表。
5. **MONEY 区压底**：绿上粉下两条折线，线间距离就是利润；右侧结算卡 `profit = $710.32` 用淡绿内嵌块收拢视线，与顶部大数字首尾呼应——**同一个数字出现两次，开在开头，收在结尾**。
6. **最底部日志**像卷宗：时间戳最暗、彩色角色标签、金额 `<b>` 提亮。它不需要被读，它只需要"看起来在被记"。

信息架构的心法：**最重要的信息 = 最大面积 + 最高亮度 + 最先扫到，三者必须同时满足**。很多仪表盘只给 KPI 大字号却不给亮度特权，结果就是"数据很多、结论没有"。

## 3. 关键设计决策逐条分析

### 决策 1：近黑青灰底，而不是纯黑
- **做法**：页面底 `#0A0E10`、卡片 `#0C0C18`，都带一点青灰倾向；叠两层粉紫氛围雾光（radial-gradient，alpha .09–.10）。
- **为什么**：纯黑会把 8% 白色发丝线、辉光、阴影全部"吃掉"，界面变成一张死纸；青灰底是"夜里机房的空气感"——黑得有温度。雾光层是"有光源"的心理暗示：SCOUT 青、RISK 粉在背景里若隐若现，角色还没出场，颜色先立了人物。
- **何时你也该用**：任何"夜间值守/监控"气质的界面。先定底色倾向（青灰=冷静、紫=神秘、绿=生化），再用雾光暗示光源位置。

### 决策 2：一个角色一种颜色，全局零混用
- **做法**：SCOUT=青、QUANT=紫、RISK=粉、ROUTER=星形粉、YOU=白；语义另立一套（绿=收入、粉=支出、琥珀=待你拍板、黄=人类动作）。每一帧里每个颜色只有一个含义。
- **为什么**：颜色是这个界面的"第二语言"，用户不读字也能追踪事件。一条青色点链从 chat app 流向路由器，用户凭颜色就知道"这是 chat 类的流量"。一旦混用，这套语言立刻变回噪声。
- **何时你也该用**：多实体并存的监控/协作界面（服务、角色、环境、租户）。先给实体定色，再禁用同色系他途。

### 决策 3：数据流用彩色点链，不用实线
- **做法**：client→router→GPU 的连线是一串小圆点（r≈2px、间距 6px、取实体色），整链匀速流动，底轨只有 `rgba(255,255,255,.05)`。
- **为什么**：实线是"结构图"，点链是"活的流量"。观众本能地把运动的点读成"正在传输的数据包"——无须动画说明，含义自明。且点链天然轻：5 股流汇入一个枢纽也不乱，若用实线早糊成一团。
- **何时你也该用**：任何要表达"流动、传输、吞吐"的连接（消息队列、ETL、网络流量）。静止的结构用线，活的流量用点。

### 决策 4：待审批用 dotted 琥珀框 + 非模态弹窗
- **做法**：待你签的客户端行是 `1px dotted` 琥珀边框 + 琥珀 10% 底 + 小字 `pending your OK`；弹窗浮在网络图上，无遮罩、不锁屏，按钮默认幽灵态、hover 才翻成实心白底深字。
- **为什么**：dotted 线的视觉语义是"虚线=未定稿"，一眼区分"已签"与"等你签"；琥珀是人类专属色（系统绝不会用），等于在色谱上立了一块"人工通道"的牌子。非模态是因为**监控不该被打断**——弹窗等你，而不是绑架你。幽灵按钮把"approve"也做成低压力操作，不会出现一个血红大按钮制造恐慌。
- **何时你也该用**：一切"机器候补、人类终审"的场景（AI 生成待发布、自动交易待确认、工单待批复）。给"等人"状态一个专属视觉词。

### 决策 5：数字 lerp 插值 + tabular-nums，永不直接跳变
- **做法**：所有计数用 `cur += (target-cur) * 0.12` 指数平滑 + 全局 `tabular-nums` 锁宽，统计行和日志同步更新。
- **为什么**：数字直接跳 = 系统在"报告"；数字平滑涨 = 系统在"运行"。前者是报表的语气，后者是生意的语气。tabular-nums 防的是布局抖动——"数字在跳但不抖"，跳的是值，站住的是版面。
- **何时你也该用**：任何实时计数（在线人数、销售额、流量）。注意配合一个主 rAF 统一驱动，别每一处自己 setInterval。
- **边界（demo 实证补遗）**：lerp 适用连续量（比率、金额、吞吐）；**离散状态计数**（待办数、在线数）若在两处语义强绑定的位置同显（如顶栏计数 ↔ 按钮文案 "N items"），慢速 lerp 会造成收敛窗内两处不同值——这就违反了"无一处假"。离散计数 snap 直写，或把系数提到 0.35+ 把收敛压缩到 300ms 内。

### 决策 6：暗态预置行（dim placeholder），而不是事后插入
- **做法**：未成交的 `voice agent` 行以 `opacity: .32` 从一开始就占位，事件发生后只点亮；GPU 列表里 `N7 Reno / N8 Paris` 同样常驻暗态，审批通过后点亮。
- **为什么**：如果事件来了才插行，列表会跳——跳就会分散注意力，注意力是监控界面最宝贵的资源。预置暗行让"变化"永远发生在固定位置，用户用余光就能感知"刚才少了什么、多了什么"。同时暗行本身也在传递信息："系统知道还有这些可能性，只是还没发生。"
- **何时你也该用**：事件流、任务队列、节点列表——凡是"集合已知、成员陆续激活"的列表。先摆好，再点亮。

### 决策 7：行间发丝线，代替卡片间距
- **做法**：客户端、GPU 节点、日志全部"方角行 + 行间 1px `rgba(255,255,255,.05)`"，左侧配 2–3px 分类色竖条。
- **为什么**：卡片块是"陈列品"语气，发丝线连续行是"账簿"语气——账簿让人相信每一条都被登记。竖条色 = 行分类的颜色索引，视线可以沿颜色竖向扫描"所有青色类"。
- **何时你也该用**：高密度列表（>6 行、需扫读）。卡片留给"一个对象一页详情"，列表用行。

### 决策 8：双折线同系，线间距即衍生指标
- **做法**：MONEY 图绿线（token revenue）上、粉线（GPU rent）下，两线垂直距离自然就是利润；面积填充只在绿线下方。
- **为什么**：省掉第三条"利润线"和图例，两线构成的"剪刀差"本身就是叙事——张口越大、今晚越赚。图表会说话的标志：指标不在图例里，在几何关系里。
- **何时你也该用**：收入 vs 成本、发送 vs 失败、预期 vs 实际——一切"差值有意义"的双序列。

### 决策 9：窗口交通灯 + 容器拟物
- **做法**：整张仪表卡顶部一条亮色标题带，左上角红黄绿三圆点（`#FF5F57/#FEBC2E/#28C840`），标题 `Grok Bot — token night shift · stopline on`。
- **为什么**：视频观众的第一反应是"这是个真应用"，而不是"这是一个网页 demo"。macOS 窗口语言是"产品感"最便宜的搬运工——三个圆点换一个信任前提。
- **何时你也该用**：概念视频、产品预告、落地页 hero 里的界面截图/演示。注意：只在"演示容器"上用，真实产品界面里这是冗余。

### 决策 10：彩色光斑 "房间"，让卡片成为夜里的灯
- **做法**：深色卡片之外，背景是低饱和彩色光斑（蓝/黄/粉晕染），卡片底部还有一截浅色区块和模糊光点。
- **为什么**：把仪表卡"放进一个空间里"——它不是贴在屏幕上的 UI，是夜里房间中一块发光的屏幕。空间感给用户的潜台词是"这是真实世界的一角"。同时光照对比让卡片更显眼：周围有多暗，卡片上的绿光就有多安心。
- **何时你也该用**：营销页/概念视频里的界面呈现。给 UI 一个"环境"，它会立刻从稿图变成产品。

## 4. 从"动态"中学设计

这段 11 秒视频里**没有一秒是完全静止的**，但你找不到任何一个传统意义上的"动效"（没有入场飞入、没有弹跳、没有转场）。它的生命力全部来自编排：

- **节奏分层**：每秒级的数字 lerp（tok/s、利润）、2 秒级的状态点呼吸、14 秒级的虚线环旋转、不定时的"事件"。三种节奏叠加 = 心电图般的"活着"证据。
- **事件驱动四件套**：一次签约事件 = ① 弹窗出现 → ② 你点 approved → ③ 客户端列表该行从暗转亮/变色 → ④ 日志追加 `04:19 you signed translator · traffic on` → ⑤ 数字跳变。多组件为同一业务事件"同步演出"——**这是"产品"和"demo"的分水岭**。demo 让组件各自表演，产品让组件合唱。
- **`you` 是演员表里的一员**：日志里 `you` 和 scout/router 并列出现（`04:19 you signed translator`）。你的动作被写进系统日志，宣告"你在这个系统里有角色"——这是最隐蔽也最有效的用户 binding。
- **克制即真实**：全部位移 0px（固定视口、零滚动），所有运动都是数值与透明度——真实监控屏从不滚动给你看。

## 5. 学完带走的三大招

1. **"床头测试"优先于"桌面测试"。** 设计监控/值守类界面时，假设用户在深夜用手机眯眼看你：一个发光大数字 + 一排彩色在岗点 + 一条"无异常"语义，先于一切详细面板。详细面板是给"出事之后"的，不是给"日常一瞥"的。
2. **给"等人类"一个专属视觉词，并让它贯穿全局。** GrokBot 的琥珀 dotted 框、`pending your OK`、`> YOU` 黄标、"approved → ✓" 构成一整套"轮到你了"语言。AI 时代界面最大的新需求就是表达人机权责——先定义"人介入点"的颜色、线型、文案，再定义其余。
3. **让组件为一个事件合唱，而不是各自独奏。** 业务事件发生时，弹窗/列表/日志/数字必须同步响应。做法上用一个事件总线 + 单一数据 store，界面上用"同一时间窗、同一语义色"的联动。同步感 = 系统感，系统感 = 信任。
