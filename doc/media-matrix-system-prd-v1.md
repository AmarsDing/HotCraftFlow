## 0. TL;DR —— 五句话结论

1. **原文档只覆盖了中段。** 既有 PRD 0.8 是优秀的「**二次加工**」规格（地址 → 文档 → 成片），但「**情报收集**」「**热点追踪**」「**市场影响分析**」三段基本空白，「**矩阵发布**」被压到 Phase2/3。重构后系统由 **5 个子系统**构成。
2. **情报 ≠ 媒体热点。** 本项目的「情报收集」明确包含：时政人物、商界精英、行业发展、科技突破，并需判断**对全球股市、货币市场、经济走势、数字货币的影响面**。这是与安全侦察类 OSINT **不同**的问题域（§5.1）。
3. **许可红线命中率很高。** 本轮实测：功能最贴合的 **TrendRadar（63k★，GPL-3.0）**、**RSSHub（46.5k★，AGPL-3.0）**、**FreshRSS（16.3k★，AGPL-3.0）** 全部撞红线。**可安全依赖的**：newsnow（MIT）、FinBERT（Apache-2.0）、ccxt（MIT）、OpenClip 等。详见 §9。
4. **开源在"影响面分析"层几乎交白卷。** 开源擅长「捞新闻 + 打情感标签」；「这条消息利好哪个板块/币种」这一层**必须自建**（规则库 + 映射表 + LLM）。详见 §5.4。
5. **不推翻已冻结的 MVP 0.8**（2026-10-20 → 12-12，2 人 8 周）。它交付 MME 核心，是本方案地基；其余子系统在其后接续排期（§11）。

## 1. 系统总览

### 1.1 一句话定义

> **全媒体内容矩阵系统（MediaMatrix）**：一套自托管的热点驱动内容流水线——持续采集国内外媒体情报、追踪热点演化、评估市场影响面、批量二次加工成多版本短视频与图文、按平台矩阵交叉分发，并把表现数据回流反哺。

### 1.2 五子系统与数据流

                           ▼
┌─────── ② TT 热点追踪系统 (Trend Tracking) ──────────────────┐
│  热度归一化 → 时序存储 → 生命周期判定 → 突发检测 → 预警      │
│      → 溯源/传播路径 → 选题评分                              │

## 3. 子系统一：情报收集系统（IC · Intelligence Collection）

### 3.1 目标与边界

| 项 | 内容 |
|----|------|
| **目标** | 持续、合规地从国内外媒体平台采集**可用于二次加工与分析**的情报条目，产出带**来源凭证与证据链**的 `IntelItem` 流 |
| **输入** | 平台热榜 / 关键词 / 订阅源 / 指定创作者 / 竞品账号 / 突发信号 |
| **输出** | `IntelItem`（归一化情报条目）+ 证据快照 + 素材指针 |
| **采集主题** | 时政人物、商界精英、行业发展、科技突破、新兴技术、社会热点 |
| **明确不做** | 不绕过登录墙 / 不破解签名 / 不采集个人信息 / 不做一键搬运（必须经 MME 二次加工） |

### 3.2 五层架构

```
L1 信源层   SourceRegistry  —— 热榜/关键词/创作者/RSS/竞品 可配置注册表，启停与频率可配
L2 采集层   Collector       —— 五路可插拔适配器：hotlist / api / rss / crawl / sidecar
L3 归一化层 Normalizer      —— 统一 IntelItem schema；URL 归一 + 内容指纹 + 语义 三级去重
L4 理解层   Extractor       —— 实体抽取(人物/机构/政策/技术/地点)、情感、摘要、可加工性
L5 治理层   Governance      —— 合规闸门、配额与速率、取证快照留存、审计
```

### 3.3 信源矩阵（国内外 × 采集路）

| 区域 | 平台/源 | 建议采集路 | 可得内容 | 姿态 |
|------|---------|-----------|----------|------|
| **国内** | 微博 / 百度 / 知乎 / 头条 | **热榜**（newsnow 已覆盖） | 热搜词、排名、链接 | **Depend newsnow** |
| | 抖音 | 热点榜 + 录播侧车 | 热点词、视频元信息 | 热榜 + 侧车 |
| | B站 | 公开 API + **RSSHub** + 热榜 | 视频元信息、UP 主动态、字幕 | Depend（较友好） |
| | 快手 / 小红书 | 热榜 + 关键词页 | 标题/热度/互动 | 抓取（严守 robots） |
| | 公众号 / 财新 / 华尔街见闻 | **RSSHub** 路由 或 Crawl4AI | 长文正文 → MD | RSSHub 独立服务 |
| | 交易所/监管公开 feed | RSS / 官方 API | 公告、政策原文 | Depend |
| | 视频号 | **受限** | — | 诚实标注不可用 |
| **国外** | YouTube | **Data API v3** + yt-dlp | 元信息、字幕、Trending | 官方 API 优先 |

### 3.4 情报分类（四类，决定下游走向）

| 类 | 说明 | 下游 |
|----|------|------|
| **A. 热点情报** | 正在上升的话题/事件 | → TT 追踪 → MME 加工 |
| **B. 素材情报** | 可直接获取的可加工素材（长视频/文章/播客） | → MME 直接建任务 |
| **C. 市场情报** | 时政/政策/公司/科技突破等可能影响市场的消息 | → **MIA 影响面分析** |
| **D. 合规情报** | 平台规则变更、版权警示、政策信号 | → 阻断/告警，进人工 |

### 3.5 功能需求（FR-INT-\*）

| ID | 名称 | 描述 | 验收标准 | 优先级 |
|----|------|------|----------|--------|
| **FR-INT-01** | 信源注册表 | 热榜/关键词/创作者/RSS/竞品五类信源可配置 | 配置驱动；新增一个信源不改代码 | **P0** |
| **FR-INT-02** | 热榜采集器 | 接入多平台热榜（**默认自部署 newsnow**） | ≥10 国内 + ≥5 国外源；单源失败不影响其他 | **P0** |

| **FR-INT-04** | 正文抽取 | URL → 干净 Markdown（复用 `FR-M16-01`，默认 Crawl4AI） | 反爬/超时/空正文三类错误可读，可手贴续跑 | **P0** |

| **FR-INT-08** | 实体抽取 | 抽取人物/机构/地点/事件/话题；**需支持中英** | 中文可用（jieba/HanLP 级）；实体可检索 | **P1** |
| **FR-INT-09** | 情报分类 | 自动归入 A/B/C/D 四类 | 可人工纠正；纠正记入样本 | **P1** |

| **FR-INT-11** | 取证快照 | 留存时间、URL、原始片段、抓取方式、响应头 | 可导出证据包（合规审计用） | **P0** |

| **FR-INT-14** | 情报检索 | 全文 + 实体 + 时间范围检索历史情报 | 可选 MCP ≤3 tool（search/get/export） | **P1** |

| **FR-INT-16** | 表现数据回流接入 | 接收 MAP 回流数据 | 更新选题权重 | **P2** |
| **FR-INT-17** | 情报简报 | 按周期生成情报简报（MD/HTML） | 可按类目/关键词定制；含来源链接 | **P2** |

## 4. 子系统二：热点追踪系统（TT · Trend Tracking）

> **IC 解决"有什么"，TT 解决"什么在涨、值不值得做、什么时候做"。**

### 4.1 目标与边界

| 项 | 内容 |
|----|------|
| **目标** | 对情报条目做**时间序列化**追踪，识别热度演化、生命周期与突发，输出可排序选题建议 |
| **输入** | `IntelItem` 流（含各平台排名与互动数快照） |
| **输出** | `TrendSeries` · `TopicCandidate` · `Alert` |
| **明确不做** | 不承诺预测准确率；不承诺覆盖全平台；不做舆情定性结论输出 |

### 4.2 跨平台热度归一化（核心难题）

各平台热度**不可直接比较**（微博热搜榜位 vs B站播放量 vs Reddit upvote）。三层设计：

| 层 | 指标 | 计算 |
|----|------|------|
| **L1 平台内** | 排名分位 `rank_pct` | `(总榜长 - 当前排名) / 总榜长` |
| | 互动强度 `eng_rate` | 互动数 / 曝光数（无曝光则退化为互动量对数分位） |
| **L2 跨平台** | 综合热度 `heat_score` (0–100) | `w1·rank_pct + w2·eng_pct + w3·freshness + w4·breadth`，权重可配 |
| **L3 动态** | 增速 `velocity` | 单位时间 `heat_score` 变化率（EWMA 平滑） |
| | 加速度 `accel` | `velocity` 变化率，用于突发检测 |

> **诚实**：`heat_score` 是**相对可比分数**非绝对热度；跨平台权重依赖人工标定，UI 须明示"分数可解释"且各因子值可见。

### 4.3 时序存储

| 项 | 建议 |
|----|------|
| 存储 | **InfluxDB 2.x**（本机已有 `D:/influxdb2-2.9.1-windows_amd64`，可直接复用）或 TimescaleDB |
| Measurement | `topic_heat`（tags: `topic_id, platform, region, category`; fields: `rank, heat_score, views, likes, comments, eng_rate`） |
| 采样 | 热榜源默认 **30 分钟**（newsnow 默认缓存 30 分钟，**勿**高于此频率）；可配 2–60 分钟 |
| 保留 | 原始快照 ≥90 天，聚合曲线 ≥1 年；超期自动降采样 |
| 消息总线 | **NATS**（本机已有 `D:/nats-server`）——采集器 → 归一化 → 追踪的流式解耦 |
| 时区 | **统一存 UTC，展示用 Asia/Shanghai**（财经跨市场对齐必须） |

### 4.4 生命周期模型（五阶段）

| 阶段 | 判据（阈值可配） | 内容策略 |
|------|------------------|----------|
| **Latent 萌芽** | 首次出现，平台数 1–2，`heat_score` < 30 | 观察，蓄稿 |
| **Rising 上升** | `velocity` > 阈值 且 持续 ≥2 采样点 | **黄金窗口**，优先加工 |
| **Peak 峰值** | `heat_score` ≥ 80 或 `velocity` 转负前 | 抢发，但竞争激烈 |
| **Decaying 衰退** | `velocity` < 0 持续 ≥3 点 | 仅做长尾解读/合集 |
| **Long-tail 长尾** | 低热度但持续存在 | 素材库沉淀，做常青内容 |

### 4.5 突发检测（三方法投票）

| 方法 | 原理 | 适用 |
|------|------|------|
| **Z-score 残差** | 对 `heat_score` 时序做 EWMA/STL 分解，残差 > `k·σ`（默认 k=3） | 平稳序列突变 |
| **双阈值增速** | `velocity > v_min` **且** `heat_score > h_min` | 通用（避免低基数噪声） |
| **榜单跃迁** | 首次进榜，或单周期排名跃升 ≥ N 位 | 排行榜型数据源 |

> **验收**：≥2 种方法命中才算突发；每次告警须附**触发依据**（哪个方法、哪个数值）；误报可人工标记用于调参。

## 5. 子系统三：市场影响分析（MIA · Market Impact Analysis）

> **新增子系统。** 依据 `media-intel-market-impact-opensource-research.md` 的需求澄清与开源调研。

### 5.1 需求澄清（关键边界）

「情报收集」在本项目中**不只是**媒体热点，还包括：

1. **采集主题**：时政人物、商界精英、行业发展、科技突破、新兴技术。
2. **分析目标**：判断该消息的**影响面**——对股市某类/某只股票的积极或负面影响、货币市场、经济走势，以及数字货币。
3. **市场范围**：**全球**各大股市 + **数字货币**。

> **明确排除**：安全侦察类 OSINT（Sherlock 用户名探测、Maigret、SpiderFoot、theHarvester 域名/邮箱枚举、Amass 子域枚举、OpenCTI 威胁情报、reNgine、IntelOwl 攻击面测绘）属于**不同问题域**，擅长用户名/子域/攻击面，**不覆盖**「媒体热点 → 市场影响面」。**不纳入**最小可跑组合，仅作边界对照。

### 5.2 开源成熟度分层（决定"哪些必须自建"）

| 层 | 开源成熟度 | 代表 |
|----|-----------|------|
| 媒体/RSS 采集与聚合 | **较高** | FreshRSS、news-please |
| 英文财经情感分类 | **较高** | FinBERT |
| 全球行情与加密行情接入 | **较高** | OpenBB、ccxt |
| 事件 → 标的映射 / 影响路径 | **低，需自建** | 人物–公司–产业链–板块–个股–币种 |
| 跨资产传导与因果校准 | **低，需自建** | 多为相关/规则分，非稳定因果 |

> **一句话**：开源擅长「把新闻捞进来并打情感/事件标签」；「这条消息拖累哪只股票、利好哪个板块/币种」这一层，几乎都要 **规则库 + LLM + 行业知识**自建。

### 5.3 分析流水线

```
IntelItem（C 类市场情报）/ TrendSeries
  → 实体链接（人物/机构/政策/技术 → 市场标的）
  → 情感与方向判断（FinBERT 英文 / LLM 中文宏观）
  → 事件聚类 → 事件卡
  → 影响面评分（情感 × 源权重 × 相关性 × 时效 TTL 衰减）
  → 跨资产传导规则（强美元 ↔ 新兴市场股/黄金/BTC，标注置信度）
  → ImpactCard（事件 + 影响路径 + 关联标的 + 置信度）
  → 行情校验（OpenBB 股 / ccxt 币，只读）→ 事后校准规则权重
```

### 5.4 必须自建的五件事（开源几乎交白卷）

1. **人物 / 政策 → 标的**（领导人表态、制裁、降息 → 指数 / 行业 ETF / 汇率 / 避险资产）
2. **行业 / 科技突破 → 产业链个股**
3. **加密叙事 → 币种**（ETF、监管、公链升级、稳定币；CryptoPanic 币标签仍不够）
4. **跨资产传导规则**（只能当**假设**，须标置信度，不得当因果结论）
5. **去重与事件聚类**（多源转载合并成一条「事件卡」再算影响）

### 5.7 加密 7×24 架构注意点

1. **双调度**：股市用交易时段密集 + 盘后摘要；加密用固定短周期（5–15 分钟）。
2. **去重与叙事合并**：加密标题党多，避免单条噪声直接映射成方向信号。
3. **时区**：统一存 UTC，展示 Asia/Shanghai；跨市事件按事件时间对齐。
4. **影响衰减**：分数带 TTL（6–24 小时），避免旧利好长期占排行榜。

### 5.8 合规（本子系统最高优先级）

1. 仅使用**公开信息**与官方/授权 API；遵守各平台 ToS 与配额。
2. 新闻正文有**版权**，适合内部分析，**不宜整篇再分发**。
3. 本组合与相关开源项目均为**研究/监测辅助**，**不是荐股或交易指令**；所有输出须带免责声明。
4. 涉及股市/汇市/加密结论请自行复核数据与监管披露；**模型输出须人工把关**。

## 10. 合规、许可与风控

### 10.1 内容合规（最高优先级）

| 风险 | 说明 | 缓解 |
|------|------|------|
| **著作权** | 二次剪辑涉改编权/信息网络传播权；矩阵分发放大风险 | ① 优先**自有/授权/CC**素材；② 二创须**实质性转化**，**禁止**原样切片搬运；③ 标注来源作者；④ 商用前法务审查 |
| **新闻版权** | 新闻正文适合内部分析，**不宜整篇再分发** | MIA 结论内部用；对外发布走二次创作 |
| **投资建议风险** | 市场影响结论可能被误读为荐股 | ① 每份 ImpactCard **强制带免责声明**；② 标注"研究/监测辅助，非投资建议"；③ 模型输出须人工把关 |
| **平台 ToS** | 自动化发布、多账号矩阵可能违约 | ① 优先官方开放平台；② 账号池克制；③ 频率限流与拟人化节奏 |
| **数据合规（PIPL）** | 采集含个人信息内容有风险 | ① 只采集**公开内容元信息与聚合统计**；② 不采集/存储用户个人信息；③ 取证快照最小必要 + 留存期 |
| **抓取合规** | 高频抓取可能构成不正当竞争 | ① 守 `robots.txt`；② 速率限制（newsnow 作者已公开呼吁"勿竭泽而渔"）；③ 优先热榜/API/RSS |
| **内容安全** | 自动加工可能产出违规内容 | ① **人工审核闸门**（FR-PUB-04）；② 敏感词与类目过滤（FR-INT-12）；③ 默认私密后再升公 |
| **直播录制** | 未授权录制风险高 | **须授权录制**；默认进人工审核 |

> **建议**：V1 以**自有素材 + 授权素材 + 平台开放 API** 为主；"热点切片搬运"路径仅在法务确认后开放（§12 Q1）。

### 10.2 工程风控

| 风险 | 缓解 |
|------|------|
| 平台风控封号 | 账号池隔离、频率限流、异常自动熔断 |
| 凭据泄露 | 本地加密（FR-M10-03 / FR-PUB-05），日志脱敏 |
| 自动化失控 | 审批门 + 默认私密 + 操作审计 + 发布总量上限 |
| 成本失控 | 费用估算（FR-M12-01）+ 云端调用总量帽 |
| 上游依赖 | newsnow/RSSHub 为第三方聚合，平台改版会失效 → **须自部署 + 直采回退**；勿高频打公共实例 |

| **Q7** | 账号矩阵规模上限？ | 风控风险 | V1 单平台 ≤3 账号，观察封号率后调整 |
| **Q8** | 是否采集**互动/评论**内容？ | PIPL 风险显著上升 | V1 只采集聚合统计，不采集个体评论内容 |
| **Q9** | 团队规模是否扩容？ | Phase 1–3 排期 | 2 人按上表；3 人可压至约 5 + 7 周 |
| **Q10** | 是否 Depend Open-Dispatch 作为 (A) 层？ | 省适配器工作量，但 ★17 个人维护 | **抄契约自研**，OD 作参考实现与 dry-run 对照 |

## 13. 诚实边界

1. **元数据漂移**：★ 数与许可为 **2026-10-17 GitHub API 实测**，会变化；引入前须复核 SPDX。
2. **OpenBB 许可待核实**：主仓库名/许可本轮未能确认，引入前必须复核。
3. **未实机验证**：多数深挖未本机端到端跑通模型/发布/采集，以 README + 源码契约为准。
4. **平台适配为规划**：§7.1 是**目标态**非已实现；国内平台开放发布能力需实际申请后确认。
5. **热度分是相对值**：`heat_score` 跨平台可比性依赖人工标定权重，**不是**绝对热度。
6. **影响面非因果**：MIA 输出是**规则分 + 相关推断**，**不是**稳定因果；跨资产传导只能当假设并标置信度。
7. **合规非法律意见**：§10 为工程侧风险清单，正式商用前须法务出具意见。
8. **一站式仍开放**：六轮调研确认"任意 URL → 深度文档 → 高质量成片"一站式无成熟 OSS；**加上采集、追踪、影响分析、矩阵发布后缺口更大**。本方案是**拼装自研**。
9. **上游依赖风险**：newsnow / RSSHub / CryptoPanic 均为第三方数据源，平台改版会导致源失效，须有直采回退。
