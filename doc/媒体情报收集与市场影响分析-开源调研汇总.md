# 媒体情报收集与市场影响分析：开源调研汇总

> 整理日期：2026-10-16（Asia/Shanghai）  
> 目标目录：`E:\project\FrameWork\doc`  
> 范围：从国内外媒体获取热点信息 → 分析对全球股市、数字货币等的影响面  
> 说明：本文汇总调研结论，仅供研究与架构参考，**不是投资建议**。

---

## 1. 需求定义（已澄清）

「信息收集」指的是：

1. **采集**：时政人物、商界精英、行业发展、科技突破、新兴技术等，从国内外各大媒体平台获取热点信息。  
2. **分析**：判断该消息的**影响面**——对股市某类/某只股票的积极或负面影响、货币市场、经济走势，以及数字货币等。  
3. **市场范围**：**全球**各大股市 + **数字货币**。

这与安全侦察类 OSINT（用户名探测、子域枚举、攻击面测绘）不是同一类问题。早期若按安全 OSINT 选型会偏离目标；本文以「媒体情报 → 市场影响」为主线。

---

## 2. 总体结论（先看这个）

开源里**几乎没有**「一键：时政人物/科技突破 → 具体股票或币种涨跌」的成熟产品。能力通常拆成多层：

| 层 | 开源成熟度 | 说明 |
|---|---|---|
| 媒体/RSS 采集与聚合 | 较高 | FreshRSS、news-please 等 |
| 英文财经情感分类 | 较高 | FinBERT 等 |
| 全球行情与加密行情接入 | 较高 | OpenBB、ccxt |
| 事件 → 标的映射 / 影响路径 | **低，需自建** | 人物–公司–产业链–板块–个股–币种 |
| 跨资产传导与因果校准 | **低，需自建** | 多为相关/规则分，非稳定因果 |

**一句话**：开源擅长「把新闻捞进来并打情感/事件标签」；「这条消息拖累哪只股票、利好哪个板块/币种」这一层，几乎都要 **规则库 + LLM + 行业知识** 自建。

## 3. 媒体情报 / 财经影响相关开源项目评选

数据来源：GitHub API 与公开 README（统计约 2026-10-16）。星标为约数。

### 3.1 采集层

#### FreshRSS — 自托管新闻聚合

| 项 | 内容 |
|---|---|
| 仓库 | https://github.com/FreshRSS/FreshRSS |
| Stars | 约 1.6 万 |
| 技术栈 | PHP，可自托管 |
| 定位 | 多用户 RSS/Atom 聚合，媒体监测的「订阅层」 |

**强项**：可自托管；多语言；WebSub 近实时；无 RSS 站点可用 XPath；有 API/CLI。  
**弱项**：不做情感/事件/股价映射；质量取决于订阅源；不是财经专用。

#### news-please — 新闻爬取与结构化抽取

| 项 | 内容 |
|---|---|
| 仓库 | https://github.com/fhamborg/news-please |
| Stars | 约 2500 |
| 技术栈 | Python（Scrapy / Newspaper 等） |
| 定位 | 通用新闻爬虫 + 正文/元数据抽取 |

**强项**：开箱可用；易嵌入流水线；可挖历史归档。  
**弱项**：站点反爬/改版易挂；中文站需自配；无情感、无标的映射。  
**合规**：仅使用公开 feed / 已授权 API，遵守站点 ToS，勿绕过付费墙或反爬做大批量转载。

#### FinNLP — 财经新闻数据源（含中美）

| 项 | 内容 |
|---|---|
| 仓库 | https://github.com/AI4Finance-Foundation/FinNLP |
| Stars | 约 1500 |
| 技术栈 | Python / Jupyter |
| 定位 | 为 FinGPT 等准备的财经文本采集（Yahoo、Finnhub、新浪、东财等） |

**强项**：中美源都有；可按公司/日期拉新闻；与 FinGPT 生态配套。  
**弱项**：仓库活跃度一般；部分源要 Token/代理；不做影响面分析。

#### CryptoPanic 接入（加密新闻）

| 项 | 内容 |
|---|---|
| 服务 | CryptoPanic 官方 API（需申请 Key，遵守 ToS 与配额） |
| 参考接入 | https://github.com/kukapay/cryptopanic-mcp-server （约数十星） |
| 定位 | 加密新闻聚合入口，常带币种标签 |

**强项**：比自己扫几十个币圈站更省事；适合 7×24 短周期拉取。  
**弱项**：依赖第三方配额；噪声与标题党多，必须去重后再打分。

### 3.2 NLP / 影响分析层

#### FinBERT — 财经情感分类

| 项 | 内容 |
|---|---|
| 仓库 | https://github.com/ProsusAI/finBERT |
| Stars | 约 2300 |
| 技术栈 | Python / PyTorch / BERT |
| 定位 | 金融领域微调情感模型（正/中/负） |

**强项**：财经文本适配好；可自托管推理；行业常用组件。  
**弱项**：偏英文；只给情感分，不抽人物/公司关系，也不直接给股价影响。

#### FinGPT — 开源金融大模型

| 项 | 内容 |
|---|---|
| 仓库 | https://github.com/AI4Finance-Foundation/FinGPT |
| Stars | 约 2.1 万 |
| 技术栈 | Python / LLM / Hugging Face |
| 定位 | 金融 LLM：情感、指令微调、Forecaster 等 demo |

**强项**：生态大；可做更复杂摘要与理解。  
**弱项**：偏研究/模型，不是稳定监测产品；算力成本高；影响面仍需自接行情与规则。

#### Market-Impact-Radar — 新闻 → 市场影响（最贴需求表述）

| 项 | 内容 |
|---|---|
| 仓库 | https://github.com/SocrAItes/Market-Impact-Radar |
| Stars | 较少（功能贴合度高） |
| 技术栈 | Python / FastAPI / SQLite / LLM |
| 定位 | 自部署：抓取 → 去重 → 事件聚类 → 按市场影响分排序 → 中文摘要与影响路径 → 识别受影响资产 → Dashboard / 企业微信 |

**强项**：产品形态最接近「消息 → 影响面」；标的可覆盖股/指数/行业/商品/外汇/债；有中文摘要路径。  
**弱项**：社区与星标小；影响分偏规则+LLM，非严格因果；依赖外部 API Key 与 LLM 成本。

#### news-event-impact-detector — 事件类型 → 远期收益

| 项 | 内容 |
|---|---|
| 仓库 | https://github.com/Refinath/news-event-impact-detector |
| Stars | 约 32 |
| 技术栈 | Python / FinBERT / 回归模型 |
| 定位 | 标题事件分类后，回归估计未来几天收益方向 |

**强项**：直接对准「事件 → 股价」；可解释（历史同类事件平均收益）。  
**弱项**：偏研究原型；事件标签偏美股公司新闻；时政/宏观冲击覆盖弱。

### 3.3 行情与数据平台层

#### OpenBB — 分析师用开放数据平台

| 项 | 内容 |
|---|---|
| 仓库 | https://github.com/OpenBB-finance/OpenBB |
| Stars | 约 7.4 万 |

**弱项**：核心是数据平台，不是影响分析引擎；部分优质源需商业 Provider。

#### ccxt — 统一加密交易所 API

| 项 | 内容 |
|---|---|
| 仓库 | https://github.com/ccxt/ccxt |
| Stars | 约 4.4 万 |
| 技术栈 | JS/TS/Python 等多语言 |
| 定位 | 100+ 交易所统一接口，读 OHLCV 成熟 |

**强项**：行业默认方案；只读公共行情通常无需交易密钥。  
**弱项**：不做新闻；交易相关能力与本方案无关，监测场景仅用只读行情。

#### （可选）microsoft/qlib

约 4.9 万星。量化研究/回测平台，适合把「新闻因子」放进收益检验；本身不做媒体采集。  
仓库：https://github.com/microsoft/qlib

## 5. 全球股市 + 数字货币：最小可跑组合

### 5.1 推荐链路（一句话）

**FreshRSS（全球媒体）+ CryptoPanic（加密新闻）→ FinBERT（快情感）[+ 可选 Market-Impact-Radar] → OpenBB（股市）+ ccxt（币价）→ Webhook / 企业微信推送**

### 5.2 分层一览

| 层 | 主力 | 弱项怎么补 |
|---|---|---|
| 采集 | FreshRSS + CryptoPanic API | 正文不全时用 news-please（合法授权范围内） |
| NLP / 影响 | FinBERT；需要中文摘要与影响路径时挂 Market-Impact-Radar | 宏观时政用通用 LLM 摘要；FinGPT 第二周再考虑 |
| 行情 | OpenBB（股）+ ccxt（币） | 加密新闻不走 ccxt，走 CryptoPanic |
| 推送 | Webhook / 企业微信 | 第一周先保证高影响条目进手机 |

### 5.3 加密 7×24 架构注意点

1. **双调度**：股市用交易时段密集 + 盘后摘要；加密用固定短周期（如 5–15 分钟）拉取。  
2. **去重与叙事合并**：加密标题党多，避免单条噪声直接映射成方向信号。  
3. **时区**：统一存 UTC，展示用 Asia/Shanghai；跨市事件按事件时间对齐。  
4. **影响衰减**：建议分数带 TTL（如 6–24 小时衰减），避免旧利好长期占排行榜。

### 5.4 第一周落地路径（合法公开源）

| 阶段 | 做什么 |
|---|---|
| Day 1–2 | 部署 FreshRSS；订阅主流国际社、监管/央行、交易所公开 feed；申请 CryptoPanic API Key |
| Day 2–3 | OpenBB 拉全球主要指数/代表性 ETF；ccxt 只读拉 BTC/ETH 等 OHLCV |
| Day 3–4 | 英文标题+摘要跑 FinBERT → 正/中/负；中文/宏观先做一句话摘要 |
| Day 4–5 | 维护两张映射小表（见 5.5）；分数 = 情感 × 源权重 × 相关性；输出偏多/偏空/中性 + 关联标的 |
| Day 5–7 | 高分推送；人工改误报；有余力再装 Market-Impact-Radar |

### 5.5 必须自建（开源几乎交白卷）

1. **人物 / 政策 → 标的**（领导人表态、制裁、降息 → 指数/行业 ETF/汇率/避险资产）  
2. **行业 / 科技突破 → 产业链个股**  
3. **加密叙事 → 币种**（ETF、监管、公链升级、稳定币等；CryptoPanic 币标签仍不够）  
4. **跨资产传导规则**（强美元 ↔ 新兴市场股 / 黄金 / BTC 等——只能当假设，标注置信度）  
5. **去重与事件聚类**（多源转载合并成一条「事件卡」再算影响）

### 5.6 起步映射表示例字段（可直接建表）

**表 A：实体 → 市场标的**

| 字段 | 说明 |
|---|---|
| entity_name | 人物/机构/政策关键词 |
| entity_type | person / org / policy / tech |
| asset_class | equity / index / fx / commodity / crypto |
| symbol | 如 SPY、^GSPC、EURUSD、BTC/USDT |
| direction_bias | risk_on / risk_off / mixed / unknown |
| confidence | 0–1 |
| notes | 人工备注 |

**表 B：叙事关键词 → 加密币种**

| 字段 | 说明 |
|---|---|
| narrative | 如 etf_approval / sec_lawsuit / network_upgrade |
| keywords | 关键词列表 |
| coins | BTC, ETH, … |
| default_sentiment_hint | positive / negative / mixed |
| ttl_hours | 建议衰减时长 |

## 6. 早期偏离说明（安全 OSINT，仅作对照）

若按「渗透/攻击面情报」搜索，常见项目包括 Sherlock、Maigret、SpiderFoot、theHarvester、Amass、OpenCTI、reNgine、IntelOwl 等。它们擅长用户名探测、子域枚举、威胁情报知识库，**不覆盖**「媒体热点 → 股市/汇市/加密影响面」。本项目选型以第 3–5 节为准，安全 OSINT 仅作边界对照，不纳入最小可跑组合。

---

## 7. 合规与使用边界

1. 仅使用**公开信息**与官方/授权 API；遵守各平台 ToS 与配额。  
2. 新闻正文有**版权**，适合内部分析，不宜整篇再分发。  
3. 本组合与相关开源项目均为**研究/监测辅助**，不是荐股或交易指令。  
4. 涉及股市/汇市/加密结论请自行复核数据与监管披露；模型输出须人工把关。
